# US-01 Frontend Detail - Dang ky tai khoan

## 1. User story

La nguoi dung moi, toi muon dang ky tai khoan bang email va mat khau de bat dau su dung AISAM.

## 2. Muc tieu frontend

- Cung cap man hinh dang ky co the su dung ngay trong frontend MVP.
- Goi dung backend register dang active trong `AISAM-BE`.
- Luu session ngay sau khi register thanh cong vi backend tra `accessToken` va `refreshToken` ngay.
- Dan nguoi dung vao flow sau dang ky phu hop voi codebase hien tai: vao khu vuc da dang nhap va uu tien chon/tao profile.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `requirement.md` muc `6.1 Authentication and Account Management` yeu cau he thong ho tro dang ky bang email va mat khau.

### Backend plan lien quan

- `BACKEND_CODE_PLAN.md` Phase 3 xac dinh auth MVP phai co `register`, `login`, `refresh`, `logout`, `me`.
- `CODEBASE_UPDATE.md` xac nhan Auth la module da active trong codebase hien tai.

### Backend implementation thuc te

- Endpoint: `POST /api/Auth/register`
- Controller tra: `200 OK`
- Response shape: `GenericResponse<TokenResponse>`
- Request DTO thuc te:
  - `email`
  - `password`
  - `confirmPassword`
  - `fullName`

### Hanh vi backend can frontend phai follow

- Backend validate:
  - email bat buoc, dung dinh dang
  - password bat buoc, toi thieu 8 ky tu
  - confirmPassword bat buoc, phai trung password
  - fullName toi da 255 ky tu
- Backend neu thanh cong se:
  - tao user moi
  - tao email verification token
  - co gang gui email verification
  - tra ve token session ngay trong response
- Backend neu email da ton tai hien tai tra `400 Bad Request`, khong phai `409 Conflict`

## 4. Pham vi frontend

### Trong pham vi

- Trang `/sign-up`
- Form register
- Validation client-side
- Submit request den backend
- Xu ly loading, error, success
- Luu auth session
- Redirect sau register
- Hien thong diep nhac verify email

### Ngoai pham vi

- Verify email page: thuoc `US-07`
- Google login: thuoc `US-11`
- Chon profile / tao profile chi la destination sau register, chi tiet thuoc `US-12` tro di

## 5. API contract can dung

### Request

`POST /api/Auth/register`

```json
{
  "email": "user@example.com",
  "password": "Password@123",
  "confirmPassword": "Password@123",
  "fullName": "User One"
}
```

### Success response

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "User registered successfully",
  "statusCode": 200,
  "data": {
    "accessToken": "string",
    "refreshToken": "string",
    "expiresAt": "2026-06-02T00:00:00Z",
    "tokenType": "Bearer",
    "user": {
      "id": "guid",
      "email": "user@example.com",
      "fullName": "User One",
      "role": 0,
      "isEmailVerified": false,
      "createdAt": "2026-06-02T00:00:00Z",
      "lastLoginAt": null
    }
  },
  "error": null
}
```

### Error response

HTTP co the gap:

- `400` khi validation loi hoac email da ton tai
- `500` khi loi he thong

Frontend phai doc loi theo thu tu uu tien:

1. `error.validationErrors`
2. `error.errorMessage`
3. `message`

## 7. Validation frontend

Frontend phai validate truoc khi submit de giam round-trip:

- `fullName`
  - optional
  - max 255 ky tu
- `email`
  - required
  - dung format email
- `password`
  - required
  - min 8 ky tu
- `confirmPassword`
  - required
  - phai trung `password`

Validation frontend khong duoc manh hon backend theo cach gay block sai scope.

## 8. Data flow frontend

1. User vao `/sign-up`
2. Nhap form
3. Frontend validate
4. Goi `POST /api/Auth/register`
5. Neu thanh cong:
   - unwrap `GenericResponse<TokenResponse>`
   - luu:
     - `accessToken`
     - `refreshToken`
     - `expiresAt`
     - `user`
   - cap nhat auth store
   - redirect vao khu vuc protected, uu tien `/profiles`
   - hien success banner/toast nhac verify email
6. Neu that bai:
   - giu nguyen du lieu form
   - bind loi field neu co `validationErrors`
   - neu email da ton tai, hien loi o muc form hoac field email

## 9. State can xu ly

### Loading state

- Disable nut submit
- Doi label nut thanh `Creating...` hoac tuong duong

### Success state

- Session duoc tao ngay
- Co thong diep:
  - account da tao thanh cong
  - can verify email khi nhan duoc mail

### Error state

- Loi validation field-level
- Loi chung tu backend
- Loi he thong `500`

## 10. Auth/session impact

Sau khi register thanh cong, frontend phai coi user da authenticated ngay.

Can cap nhat:

- `auth-store`
- API client bearer token memory/persisted state
- redirect logic cho public/protected routes

Public route guard can tu dong khong cho quay lai `/sign-up` neu user da authenticated.

## 11. Dieu huong sau dang ky

### Muc tieu

Do frontend hien tai da co flow profile, route sau dang ky nen la:

- `/profiles`

### Ly do

- Phu hop voi flow MVP hien tai cua codebase
- User da co token ngay
- Chua can dua user ve login

## 12. Acceptance criteria

### AC-01

Khi nguoi dung nhap du thong tin hop le va submit, frontend gui dung request den `POST /api/Auth/register`.

### AC-02

Khi backend tra thanh cong, frontend luu session vao auth store va dieu huong vao khu vuc protected.

### AC-03

Khi backend tra `isEmailVerified = false`, frontend hien thong diep nhac verify email, nhung khong chan user tiep tuc vao app.

### AC-04

Khi `confirmPassword` khong khop, frontend chan submit va hien loi tai field.

### AC-05

Khi backend tra loi email da ton tai hoac validation loi, frontend hien loi ro rang va giu nguyen gia tri nguoi dung da nhap.

### AC-06

Khi co loi he thong `500`, frontend hien generic error state co the hieu duoc va khong lam vo form.

## 14. Ghi chu implementation

- Khong duoc viet frontend theo gia dinh `register` tra `201`; backend hien tai tra `200`.
- Khong duoc viet frontend theo gia dinh `register` chi tao account ma khong login; backend hien tai login ngay sau register.
- Neu sau nay backend doi contract, story nay phai duoc cap nhat truoc khi refactor frontend flow.
