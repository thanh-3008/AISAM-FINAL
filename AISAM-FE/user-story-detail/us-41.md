# US-41 - Quản lý lịch đăng bài

## 1. User Story

**Là** người dùng,
**tôi muốn** xem, cập nhật, xoá và theo dõi upcoming schedules để điều chỉnh kế hoạch nội dung,
**để** có thể chủ động quản lý lịch đăng bài và phản ứng kịp thời khi có thay đổi.

---

## 2. Mục tiêu

Cung cấp trang `/schedules` với danh sách tất cả content schedules của profile đang active, hỗ trợ phân trang, filter theo status, xem upcoming schedules riêng, xem chi tiết schedule, cập nhật thời gian/page đích, và xoá (hủy) schedule. Feature này giúp người dùng có cái nhìn tổng quan và kiểm soát toàn bộ lịch đăng bài.

---

## 3. Phạm vi

### Trong phạm vi

- Trang `/schedules` hiển thị danh sách tất cả schedules (paged, 10 items/page).
- Mỗi schedule item hiển thị: content title, page name, scheduled time (relative + absolute), status badge (Pending/Processing/Completed/Failed), attempt count, last error (nếu Failed).
- Filter tabs theo status: All, Pending, Processing, Completed, Failed.
- **Upcoming section** (đầu trang): 5 schedules sắp tới (từ `GET /api/content-schedules/upcoming`).
- Pagination controls (page numbers, prev/next).
- Click schedule → mở detail modal với thông tin đầy đủ.
- Detail modal hiển thị: content title, page name, scheduled time (absolute), status, attempt count, last error, created at.
- **Edit action** từ detail modal: cho phép thay đổi thời gian (date/time picker) và/hoặc page đích.
- **Delete action** từ detail modal: dialog xác nhận → soft delete schedule.
- **Cancel action** inline: nút "Cancel" trên Pending schedule items.
- Toast success/error cho update và delete.
- Loading skeleton, empty state, error state.

### Ngoài phạm vi

- Tạo schedule mới: US-40.
- Recurring schedule (lặp lại): deferred (BE có `RepeatTypeEnum` nhưng chưa dùng MVP).
- Publish ngay (Publish Now): US-34.
- Dashboard schedule counts: US-43.
- Notification list (notification về schedule): US-36/US-37.
- Worker xử lý schedule đến hạn: BE `ScheduledPostingService`.

## 4. Actor

- **Chính:** Người dùng đã đăng nhập, có active profile, có ít nhất một content schedule đã tạo.
- **Phụ:** Backend API (`ContentSchedulesController`, `ContentScheduleService`).

## 5. Tiền điều kiện

- Người dùng đã đăng nhập và có JWT token hợp lệ.
- Người dùng đã chọn active profile (`X-Profile-Id` header).
- Backend `ContentSchedulesController` đã triển khai (Phase D).
- Có ít nhất một schedule record trong DB (tạo từ US-40).

## 6. Luồng nghiệp vụ chính

### 6.1 Xem danh sách schedules

1. Người dùng navigate đến `/schedules` (từ sidebar, "Xem lịch đăng" trong Schedule modal US-40, hoặc URL trực tiếp).
2. Frontend gọi `GET /api/content-schedules?page=1&pageSize=10`.
3. Hiển thị:
   - **Upcoming section** (đầu trang): 5 schedules sắp tới từ `GET /api/content-schedules/upcoming?limit=5`.
   - **Filter tabs**: All, Pending, Processing, Completed, Failed.
   - **Danh sách**: mỗi item hiển thị content title, page name, scheduled time (relative + absolute date), status badge, attempt count.
4. Status badge với màu sắc:
   - Pending: màu xanh dương "Chờ xử lý".
   - Processing: màu vàng/cam "Đang xử lý".
   - Completed: màu xanh lá "Hoàn thành".
   - Failed: màu đỏ "Thất bại".
5. Pagination: page numbers + prev/next.

### 6.2 Xem upcoming schedules

1. Đầu trang `/schedules` hiển thị section "Sắp tới" với tối đa 5 items.
2. Mỗi item hiển thị: content title, page name, scheduled time (relative + absolute).
3. Click item → mở detail modal.
4. Nếu không có upcoming, section ẩn.

### 6.3 Xem chi tiết schedule

1. Click schedule item → mở detail modal.
2. Modal hiển thị:
   - Content title (link đến content detail).
   - Page name (integration).
   - Scheduled time: absolute format (e.g., "15:00, Thứ Tư, 10/06/2026").
   - Executed at: nếu Completed, hiển thị thời gian thực thi.
   - Status badge.
   - Attempt count.
   - Last error: nếu Failed, hiển thị error message.
   - Created at.
3. Actions:
   - Nếu Pending: nút "Edit" và nút "Cancel".
   - Nếu Processing: disabled buttons (đang xử lý, không thể thay đổi).
   - Nếu Completed: nút "View Post" (nếu có post record liên quan).
   - Nếu Failed: nút "Edit" (để thay đổi thời gian và retry) và nút "Cancel".

### 6.4 Cập nhật schedule (Edit)

1. Từ detail modal, nhấn "Edit" → modal chuyển sang chế độ edit.
2. Hiển thị: date/time picker (tương tự US-40) và page selector (dropdown list pages).
3. User thay đổi thời gian và/hoặc page, nhấn "Save".
4. Frontend gọi `PUT /api/content-schedules/{scheduleId}` với `{ integrationId?, scheduledAt? }`.
5. Toast "Đã cập nhật lịch đăng."
6. Detail modal cập nhật thông tin mới.
7. Nếu schedule đã Completed → không thể edit (BE trả lỗi).

### 6.5 Xoá schedule (Cancel)

1. Từ detail modal, nhấn "Cancel" → dialog xác nhận.
2. Dialog: "Huỷ lịch đăng này?" + "Lịch đăng cho '{contentTitle}' lúc {time} sẽ bị huỷ." + [Cancel] [Confirm Cancel].
3. Xác nhận → gọi `DELETE /api/content-schedules/{scheduleId}`.
4. Toast "Đã huỷ lịch đăng."
5. Đóng dialog, xoá item khỏi danh sách.
6. BE tạo notification "Schedule deleted" (tự động).

### 6.6 Inline cancel (từ list)

1. Trên list item của Pending schedule, hiển thị nút "Cancel" nhỏ.
2. Click → dialog xác nhận (giống 6.5).
3. Flow tương tự.

## 7. Luồng ngoại lệ

| Mã | Trường hợp | Kết quả mong đợi |
| --- | --- | --- |
| EX-01 | API list lỗi | Error state + nút "Thử lại". |
| EX-02 | Không có schedule nào | Empty state: "Chưa có lịch đăng nào." + nút "Tạo lịch đăng" (→ Content List). |
| EX-03 | API upcoming lỗi | Ẩn upcoming section, không ảnh hưởng danh sách chính. |
| EX-04 | Update schedule đã Completed | Backend trả 400 "Completed schedules cannot be updated."; toast lỗi. |
| EX-05 | Delete schedule không tồn tại | Backend trả 404; toast "Lịch đăng không tồn tại." |
| EX-06 | Update với thời gian quá khứ | Backend validation fail; toast lỗi. |
| EX-07 | Filter không có kết quả | "Không có lịch đăng nào với trạng thái '{status}'." |
| EX-08 | Schedule đến hạn đang chờ xử lý mà user cancel | Cho phép cancel; nếu worker đã bắt đầu xử lý, schedule chuyển Processing, user không thể cancel. |

## 8. Quy tắc nghiệp vụ

| Mã | Quy tắc |
| --- | --- |
| BR-01 | Schedule list sắp xếp theo `ScheduledAt` ascending (gần nhất trước) — BE repository mặc định `OrderByDescending(CreatedAt)`, FE có thể sort lại. |
| BR-02 | Upcoming schedules filter `status = Pending` AND `ScheduledAt > now`. |
| BR-03 | Completed schedules không thể update. |
| BR-04 | Delete là soft-delete (`IsDeleted = true`). |
| BR-05 | Khi delete schedule, BE tự động tạo notification "Schedule deleted" (type PostScheduled). |
| BR-06 | Status `Processing` có nghĩa là worker đang publish; không thể update hay delete. |
| BR-07 | `LastError` chỉ có giá trị khi status = Failed. |

## 12. Acceptance Criteria

### AC-01 - Danh sách schedules

**Given** người dùng vào trang `/schedules`
**When** trang load
**Then** gọi `GET /api/content-schedules?page=1&pageSize=10`
**And** hiển thị danh sách schedule items với content title, page name, time, status badge.

### AC-02 - Upcoming section

**Given** trang `/schedules` load
**Then** gọi `GET /api/content-schedules/upcoming?limit=5`
**And** hiển thị 5 schedules sắp tới đầu trang.

### AC-03 - Filter tabs

**Given** có schedules với nhiều status
**When** click filter tab "Pending"
**Then** danh sách filter chỉ hiển thị Pending schedules.

### AC-04 - Detail modal

**Given** click schedule item
**Then** mở detail modal với đầy đủ thông tin và actions tương ứng.

### AC-05 - Update schedule

**Given** detail modal đang mở cho Pending schedule
**When** click Edit → thay đổi thời gian và/hoặc page → Save
**Then** gọi `PUT /api/content-schedules/{id}`
**And** modal cập nhật thông tin mới
**And** toast "Đã cập nhật lịch đăng."

### AC-06 - Cancel schedule

**Given** detail modal đang mở
**When** click Cancel → confirm
**Then** gọi `DELETE /api/content-schedules/{id}`
**And** item biến mất khỏi danh sách
**And** toast "Đã huỷ lịch đăng."

### AC-07 - Inline cancel

**Given** Pending schedule item trong list
**When** click nút "Cancel" inline
**Then** mở dialog xác nhận → confirm → delete.

### AC-08 - Completed không thể edit

**Given** Completed schedule
**Then** detail modal không hiển thị nút Edit
**And** hiển thị nút "View Post".

### AC-09 - Processing không thể cancel

**Given** Processing schedule
**Then** detail modal không hiển thị Edit hay Cancel.

### AC-10 - Failed schedule có Retry

**Given** Failed schedule
**When** click Retry
**Then** mở edit mode, user có thể thay đổi thời gian rồi save.

### AC-11 - Phân trang

**Given** có nhiều hơn 10 schedules
**Then** hiển thị pagination controls.

### AC-12 - Empty state

**Given** không có schedule nào
**Then** hiển thị empty state + nút "Tạo content mới".

import { useState, useMemo } from "react";
import { scheduleApi } from "@/features/schedules/api/schedule-api";
import type { ScheduleStatusFilter } from "@/features/schedules/types/schedule";

export function useSchedules() {
  const [page, setPage] = useState(1);
  const [filter, setFilter] = useState<ScheduleStatusFilter>("All");

  const listQuery = useQuery({
    queryKey: ["content-schedules", page],
    queryFn: () => scheduleApi.getPaged(page, 10),
  });

  const upcomingQuery = useQuery({
    queryKey: ["content-schedules", "upcoming"],
    queryFn: () => scheduleApi.getUpcoming(5),
  });

  // Client-side filter by status
  const filteredData = useMemo(() => {
    if (!listQuery.data?.data) return [];
    if (filter === "All") return listQuery.data.data;
    return listQuery.data.data.filter((item) => item.status === filter);
  }, [listQuery.data, filter]);

  return {
    schedules: filteredData,
    allSchedules: listQuery.data?.data ?? [],
    totalCount: listQuery.data?.totalCount ?? 0,
    totalPages: listQuery.data?.totalPages ?? 0,
    page,
    setPage,
    filter,
    setFilter,
    upcoming: upcomingQuery.data ?? [],
    isListLoading: listQuery.isLoading,
    isUpcomingLoading: upcomingQuery.isLoading,
    isListError: listQuery.isError,
    isUpcomingError: upcomingQuery.isError,
    refetchList: listQuery.refetch,
    refetchUpcoming: upcomingQuery.refetch,

function ScheduleEditForm({
  schedule,
  onSave,
  onCancel,
  isPending,
}: {
  schedule: ContentScheduleDto;
  onSave: (data: UpdateContentScheduleRequest) => void;
  onCancel: () => void;
  isPending: boolean;
}) {
  const [scheduledAt, setScheduledAt] = useState<Date | null>(
    new Date(schedule.scheduledAt)
  );
  const [integrationId, setIntegrationId] = useState(schedule.integrationId);
  const [timeError, setTimeError] = useState<string | null>(null);
  const minDate = addMinutes(new Date(), 15);
  const { data: integrations } = useIntegrationsByBrand(/* cần brandId từ content */);

  const validateTime = (date: Date | null): boolean => {
    if (!date) { setTimeError("Vui lòng chọn thời gian."); return false; }
    if (date.getTime() < Date.now() + 15 * 60_000) {
      setTimeError("Thời gian phải cách hiện tại ít nhất 15 phút.");
      return false;
    }
    setTimeError(null);
    return true;
  };

  const handleSave = () => {
    if (!validateTime(scheduledAt)) return;
    const payload: UpdateContentScheduleRequest = {};
    if (scheduledAt) payload.scheduledAt = scheduledAt.toISOString();
    if (integrationId !== schedule.integrationId) payload.integrationId = integrationId;
    onSave(payload);
  };

  return (
    <div className="space-y-4">
      <ScheduleDatetimePicker
        value={scheduledAt}
        onChange={setScheduledAt}
        minDate={minDate}
        error={timeError}
      />
      <div className="space-y-1.5">
        <label className="text-sm font-medium">Page</label>

          <SelectTrigger>
            <SelectValue />
