# US-44 - Tạo checkout subscription qua PayOS

## 1. User Story

**Là** người dùng,
**tôi muốn** xem các gói subscription, tạo checkout để thanh toán qua PayOS, và theo dõi subscription đang active,
**để** có thể nâng cấp/gia hạn gói dịch vụ cho profile của mình.

---

## 2. Mục tiêu

Cung cấp trang `/payment` cho phép người dùng xem danh sách gói subscription (Free, Plus, Premium), chọn gói, điền/cấu hình thông tin (nếu cần), và gọi `POST /api/payment/checkout` để khởi tạo phiên thanh toán PayOS. Sau khi thanh toán, hiển thị trạng thái giao dịch và subscription đang active. Feature này cũng hiển thị quota summary cho gói hiện tại.

---

## 3. Phạm vi

### Trong phạm vi

- Trang `/payment` thay thế placeholder hiện tại.
- Hiển thị danh sách gói subscription (hardcoded plan configs từ FE):
  - **Free**: $0, quota posts 5/tháng, 1 platform, 1 account, analysis Basic.
  - **Plus**: có phí (giá hardcoded FE), quota posts nâng cao, AI content daily, 2 platforms, 2 accounts, analysis Plus.
  - **Premium**: có phí, quota posts cao nhất, AI content mỗi ngày, 3 platforms, 3 accounts, analysis Premium.
- Hiển thị current subscription card:
  - Gọi `GET /api/payment/subscription/current` → tên plan, status, start date, end date.
  - Nếu không có subscription: hiển thị "Bạn chưa có gói active" + CTA chọn gói.
- Hiển thị quota summary card:
  - Gọi `GET /api/quota/profile/{profileId}` → thanh progress bar cho Prompt và Post quota.
- Click "Chọn gói" → gọi `POST /api/payment/checkout` với `PlanCode`, `ReturnUrl`, `CancelUrl`.
  - **ReturnUrl**: `${window.location.origin}/payment?checkout=success`.
  - **CancelUrl**: `${window.location.origin}/payment?checkout=cancelled`.
- Nhận response từ checkout API → redirect đến `CheckoutUrl` (PayOS payment page).
- Khi quay lại từ PayOS (callback), kiểm tra query param `checkout`:
  - `?checkout=success` → Toast "Thanh toán thành công" + refetch current subscription.
  - `?checkout=cancelled` → Toast "Đã hủy thanh toán" + không thay đổi.
  - Các trường hợp khác → không action.
- Xử lý error codes:
  - `PAYOS_NOT_CONFIGURED` (503) → toast "Cổng thanh toán chưa sẵn sàng" + disable checkout button.
  - Lỗi khác (network, 500) → toast lỗi generic.
- Loading state cho checkout button (spinner khi đang gọi API).
- Plan cards có hover effect, disabled cho plan đang active.
- Payment history list (tối giản):
  - Gọi `GET /api/payment/history?Page=1&PageSize=10`.
  - Hiển thị bảng: Ngày, Phương thức, Số tiền, Trạng thái.
  - Status badge: Pending (vàng), Success (xanh), Failed (đỏ), Refunded (xám).

### Ngoài phạm vi

- Dynamic plan CRUD từ admin (post-MVP).
- Refund workflow đầy đủ: deferred.
- Billing portal đầy đủ: deferred.
- Auto-renew toggle UI: deferred.
- Invoice download: deferred.
- Phân trang payment history (MVP chỉ hiển thị 10 gần nhất): post-MVP.
- Webhook handling (BE handles, FE không cần tương tác): ngoài scope.
- Quota enforcement UI (chỉ hiển thị visualization, enforcement đã được BE xử lý).

- Người dùng đã đăng nhập và có JWT access token hợp lệ.
- Người dùng đã chọn active profile (`X-Profile-Id` header).
- Backend `PaymentController` và `QuotaController` đã triển khai (Phase E).

## 6. Luồng nghiệp vụ chính

### 6.1 Xem trang Payment

1. Người dùng vào `/payment`.
2. Frontend gọi 3 API song song:
   - `GET /api/payment/subscription/current`.
   - `GET /api/quota/profile/{activeProfileId}`.
   - `GET /api/payment/history?Page=1&PageSize=10`.
3. Hiển thị các section:
   - **Current Subscription Card** (nếu có).
   - **Quota Summary** (thanh progress bar).
   - **Plan Selection** (3 cards: Free, Plus, Premium).
   - **Payment History** (bảng 5-10 gần nhất).

### 6.2 Chọn gói và checkout

1. Người dùng click "Chọn gói" trên một plan card.
2. Nếu plan đó đang active → disabled, không thể click.
3. Nếu plan khác → confirm dialog (nếu cần).
4. Call `POST /api/payment/checkout` với body:
   ```json
   { "planCode": "plus", "returnUrl": "https://.../payment?checkout=success", "cancelUrl": "https://.../payment?checkout=cancelled" }
   ```
5. Response success → `window.location.href = response.data.checkoutUrl`.
6. Response error → toast lỗi tương ứng.

### 6.3 Callback từ PayOS

1. PayOS redirect user về `returnUrl` hoặc `cancelUrl`.
2. Frontend parse query param `checkout`:
   - `?checkout=success` → toast "Thanh toán thành công!", refetch subscription + quota + history.
   - `?checkout=cancelled` → toast "Bạn đã hủy thanh toán."
   - Không có param → render trang payment bình thường.
3. Sau 3 giây, xóa query param khỏi URL (replaceState).

### 6.4 Xem subscription đang active

1. Nếu có active subscription:
   - Tên plan, status (Active/Inactive), start date, end date.
   - Badge màu xanh "Active".
2. Nếu không có subscription:
   - Card với message "Bạn chưa có gói active, vui lòng chọn gói bên dưới."

### 6.5 Xem quota summary

1. Hiển thị 2 thanh progress bar:
   - **Prompt Quota**: `PromptUsage / PromptQuotaLimit` → % fill.
     - Label: "AI Content: X / Y hôm nay".
   - **Post Quota**: `PostUsage / PostQuotaLimit` → % fill.
     - Label: "Bài đăng: X / Y tháng này".
2. Màu sắc thanh:
   - > 80%: đỏ (sắp hết quota).
   - 50-80%: vàng (còn ít).
   - < 50%: xanh (còn nhiều).
3. Nếu `PostRemaining = 0` hoặc `PromptRemaining = 0`: hiển thị warning icon + text "Đã hết quota, vui lòng nâng cấp gói."

## 9. API Contracts

### 9.1 Create Checkout

```
POST /api/payment/checkout
```

#### Headers
```http
Authorization: Bearer <access-token>
X-Profile-Id: <owned-profile-guid>
```

#### Request Body
```json
{
  "planCode": "plus",
  "returnUrl": "https://app.aisam.com/payment?checkout=success",
  "cancelUrl": "https://app.aisam.com/payment?checkout=cancelled"
}
```

#### Response (200 OK) - PayOS configured
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Checkout request created.",
  "data": {
    "checkoutUrl": "https://pay.payos.vn/payment/abc123",
    "paymentLinkId": "abc123",
    "orderCode": "123456789"
  },
  "timestamp": "2026-06-03T15:00:00Z"
}
```

#### Response (503 Service Unavailable) - PayOS NOT configured
```json
{
  "success": false,
  "statusCode": 503,
  "message": "PayOS is not configured.",
  "error": {
    "errorCode": "PAYOS_NOT_CONFIGURED",
    "errorMessage": "PayOS is not configured."
  },
  "timestamp": "2026-06-03T15:00:00Z"
}
```


#### Response (200 OK)

## 12. Acceptance Criteria

### AC-01 - Hiển thị trang Payment

**Given** người dùng vào `/payment`
**When** trang load
**Then** gọi 3 API song song: current subscription, quota, payment history
**And** hiển thị các section tương ứng.

### AC-02 - Hiển thị danh sách gói

**Given** trang payment đã load
**Then** hiển thị 3 plan cards: Free, Plus, Premium với thông tin chi tiết.

### AC-03 - Checkout gói có phí

**Given** người dùng click "Chọn gói" trên Plus hoặc Premium
**When** API checkout trả thành công
**Then** redirect đến `checkoutUrl` từ PayOS.

### AC-04 - Handle PAYOS_NOT_CONFIGURED

**Given** PayOS chưa được config
**When** người dùng click "Chọn gói"
**Then** toast "Cổng thanh toán chưa sẵn sàng"
**And** disable checkout button.

### AC-05 - Hiển thị active subscription

**Given** profile có active subscription
**Then** hiển thị subscription card với plan name, status, date range.

### AC-06 - Hiển thị quota summary

**Given** profile có active subscription
**Then** hiển thị 2 progress bar: Prompt Quota và Post Quota với màu sắc phù hợp.

### AC-07 - Hiển thị payment history

**Given** profile có payment history
**Then** hiển thị bảng với các cột: ngày, phương thức, số tiền, trạng thái.

### AC-08 - Callback từ PayOS

**Given** PayOS redirect về `/payment?checkout=success`
**When** trang load
**Then** toast "Thanh toán thành công!" + refetch subscription/quota/history.

### AC-09 - No active subscription

**Given** profile không có active subscription
**Then** subscription card hiển thị "Bạn chưa có gói active"
**And** quota section ẩn.

### AC-10 - Loading skeleton

**Given** API đang xử lý
**Then** hiển thị skeleton phù hợp cho từng section.

```tsx
        label="📬 Bài đăng"
        usage={quota.postUsage}
        limit={quota.postQuotaLimit}
        period="tháng này"
      />
    </div>
  );
}

function ProgressBar({
  label,
  usage,
  limit,
  period,
}: {
  label: string;
  usage: number;
  limit: number;
  period: string;
}) {
  const percentage = limit > 0 ? (usage / limit) * 100 : 0;
  const colorClass =
    limit === 0
      ? "bg-muted"
      : percentage > 80
        ? "bg-red-500"
        : percentage > 50
          ? "bg-amber-500"
          : "bg-green-500";
  const remaining = Math.max(0, limit - usage);

  return (
    <div>
      <div className="mb-1 flex justify-between text-xs">
        <span className="text-muted-foreground">
          {label} <span className="font-medium">{usage} / {limit}</span> {period}
        </span>
        {limit > 0 ? (
          <span className={remaining < limit * 0.2 ? "text-red-500 font-medium" : "text-muted-foreground"}>
            Còn {remaining}
          </span>
        ) : (
          <span className="text-muted-foreground">Không có</span>
        )}
      </div>
      <div className="h-2 w-full overflow-hidden rounded-full bg-muted">
        <div
          className={`h-full rounded-full transition-all ${colorClass}`}
          style={{ width: `${Math.min(percentage, 100)}%` }}
        />
      </div>
    </div>
  );
}
```
