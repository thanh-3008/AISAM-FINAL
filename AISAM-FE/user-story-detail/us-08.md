# US-08 Frontend Detail - Gui lai email xac minh

## 1. User story

La nguoi dung chua xac minh email, toi muon yeu cau gui lai email verification de hoan tat kich hoat tai khoan.

## 2. Muc tieu frontend

- Cung cap man hinh resend verification de user co the tu thao tac.
- Goi dung endpoint backend hien co.
- Hien thong diep trung tinh de dung voi behavior an thong tin cua backend.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `requirement.md` muc `6.1` co email verification.

### Backend implementation thuc te

- Endpoint: `POST /api/Auth/verify-email/resend`
- Request body:
  - `email`
- Response thanh cong luon la `200 OK`

### Hanh vi backend can frontend phai follow

- Backend khong tiet lo email co ton tai hay da verify chua
- Message tra ve:
  - `If the email exists and is not verified, a verification email has been sent`
- Ngay ca khi email khong ton tai hoac da verified, backend van tra `200`

## 4. Pham vi frontend

### Trong pham vi

- Trang `/resend-verification`
- Form nhap email
- Hien neutral success state

### Ngoai pham vi

- Thuc hien verify token: thuoc `US-07`

## 5. API contract can dung

### Request

`POST /api/Auth/verify-email/resend`

```json
{
  "email": "user@example.com"
}
```

### Success response

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "If the email exists and is not verified, a verification email has been sent",
  "statusCode": 200,
  "data": null,
  "error": null
}
```

### Error response

- Thuc te controller co catch-all va van tra `200` voi message trung tinh trong phan lon truong hop
- `500` khong nen la UX expectation chinh

## 6. UI/UX spec

### Route

- `/resend-verification`

### Form fields

1. `email`
   - required
   - email format

### CTA

- `Resend verification email`

### Success copy

- Hien copy trung tinh theo backend

## 7. Validation frontend

- Email bat buoc
- Dung format email

## 8. Data flow frontend

1. User vao trang resend verification
2. Nhap email
3. Frontend validate
4. Goi `POST /api/Auth/verify-email/resend`
5. Hien neutral success message

## 9. State can xu ly

### Loading state

- Disable CTA

### Success state

- Hien message da gui neu email hop le va chua verify, nhung khong xac nhan ton tai email

### Error state

- Validation phia client
- Neu co loi he thong bat thuong, hien generic error state

## 10. Auth/session impact

- Khong thay doi auth session
- Co the duoc dung boi user chua login hoac da login

## 11. Dieu huong sau submit

- Khong can redirect
- Co the giu user tren cung trang de nhap lai email khac neu can

## 12. Acceptance criteria

### AC-01

Frontend gui dung request den `POST /api/Auth/verify-email/resend`.

### AC-02

Sau submit thanh cong, frontend hien neutral success state, khong tiet lo email co ton tai hay khong.

### AC-03

Frontend validate format email truoc khi submit.

## 13. Test cases frontend

### FE-01

Chan submit khi email sai format.

### FE-02

Submit thanh cong hien message trung tinh dung voi backend.

### FE-03

Pending state disable nut submit.

## 14. Ghi chu implementation

- Khong viet UI theo gia dinh backend se tra `404 email not found`; backend co chu dich tra neutral response.
- Neu user tu verify page di sang resend page, co the prefill email neu frontend dang co du lieu.
