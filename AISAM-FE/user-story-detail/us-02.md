# US-02 Frontend Detail - Dang nhap tai khoan

## 1. User story

La nguoi dung da co tai khoan, toi muon dang nhap bang email va mat khau de truy cap AISAM.

## 2. Muc tieu frontend

- Cung cap trang dang nhap co the dung ngay voi backend hien tai.
- Goi dung API `login` dang active trong `AISAM-BE`.
- Luu session sau khi login thanh cong.
- Dieu huong nguoi dung vao flow chon profile thay vi de o trang public.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `requirement.md` muc `6.1 Authentication and Account Management` yeu cau ho tro dang nhap va JWT-based authentication.

### Backend plan lien quan

- `BACKEND_CODE_PLAN.md` Phase 3 xac dinh `login` la mot phan cua Auth MVP.
- `CODEBASE_UPDATE.md` Phase A xac nhan Auth dang la module da active.

### Backend implementation thuc te

- Endpoint: `POST /api/Auth/login`
- Controller tra: `200 OK`
- Response shape: `GenericResponse<TokenResponse>`
- Request DTO:
  - `email`
  - `password`

### Hanh vi backend can frontend phai follow

- Backend validate:
  - email bat buoc, dung format
  - password bat buoc
- Backend neu sai thong tin dang nhap tra `401 Unauthorized`
- Error message backend hien tai: `Invalid email or password`
- Login thanh cong se tra:
  - `accessToken`
  - `refreshToken`
  - `expiresAt`
  - `tokenType`
  - `user`

## 4. Pham vi frontend

### Trong pham vi

- Trang `/login`
- Form login email/password
- Validation client-side
- Xu ly login success/error
- Luu auth session
- Redirect sau login

### Ngoai pham vi

- Google login: thuoc `US-11`
- Forgot/reset password: thuoc `US-09`, `US-10`
- Verify email page chi la thong diep phu, logic verify thuoc `US-07`

## 5. API contract can dung

### Request

`POST /api/Auth/login`

```json
{
  "email": "user@example.com",
  "password": "Password@123"
}
```

### Success response

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "Login successful",
  "statusCode": 200,
  "data": {
    "accessToken": "string",
    "refreshToken": "string",
    "expiresAt": "2026-06-02T00:00:00Z",
    "tokenType": "Bearer",
    "user": {
      "id": "guid",
      "email": "user@example.com",
      "fullName": "User One",
      "role": 0,
      "isEmailVerified": false,
      "createdAt": "2026-06-01T00:00:00Z",
      "lastLoginAt": "2026-06-02T00:00:00Z"
    }
  },
  "error": null
}
```

### Error response

- `401` khi sai email hoac mat khau
- `500` khi loi he thong

Frontend phai doc loi theo thu tu:

1. `error.validationErrors`
2. `error.errorMessage`
3. `message`

## 6. UI/UX spec

### Route

- Route chinh: `/login`

### Layout

- Dung public auth layout
- Co link sang `/sign-up`
- Co link sang `/forgot-password`

### Form fields

1. `email`
   - label: `Email`
   - required
2. `password`
   - label: `Password`
   - required

### CTA

- Primary CTA: `Login`
- Secondary CTA:
  - `Create account`
  - `Forgot password?`

## 7. Validation frontend

- `email`
  - required
  - dung format email
- `password`
  - required

Khong them password policy o login vi backend khong validate theo cach do trong endpoint nay.

## 8. Data flow frontend

1. User vao `/login`
2. Nhap email va password
3. Frontend validate
4. Goi `POST /api/Auth/login`
5. Neu thanh cong:
   - unwrap `GenericResponse<TokenResponse>`
   - luu:
     - `accessToken`
     - `refreshToken`
     - `expiresAt`
     - `user`
   - cap nhat auth store
   - redirect sang `/profiles`
6. Neu that bai:
   - giu nguyen form
   - hien loi chung `Invalid email or password`

## 9. State can xu ly

### Loading state

- Disable nut submit
- Hien label `Logging in...`

### Success state

- Session duoc luu
- Public guard khong cho quay lai `/login`

### Error state

- Sai thong tin dang nhap
- Loi he thong `500`

## 10. Auth/session impact

Sau login thanh cong, frontend phai coi user da authenticated ngay.

Can cap nhat:

- `auth-store`
- API client bearer token
- redirect logic cua protected/public routes

## 11. Dieu huong sau dang nhap

- Route sau login: `/profiles`

Ly do:

- Codebase frontend da co flow profile selection
- Backend auth hien tai khong co active profile trong token

## 12. Acceptance criteria

### AC-01

Frontend gui dung request den `POST /api/Auth/login` khi form hop le.

### AC-02

Khi backend tra thanh cong, frontend luu token va user vao auth store.

### AC-03

Khi login thanh cong, frontend dieu huong sang `/profiles`.

### AC-04

Khi backend tra `401`, frontend hien loi dang nhap ro rang va khong xoa gia tri dang nhap cua user.

### AC-05

Khi user da authenticated ma truy cap `/login`, frontend redirect sang khu protected.

## 14. Ghi chu implementation

- Khong viet frontend theo gia dinh login tra `204` hay chi tra token string; backend tra `GenericResponse<TokenResponse>`.
- Khong redirect ve `/dashboard` ngay neu flow thuc te van can profile selection.
- `role` co the serialize dang so hoac string tuy backend JSON setting; frontend can parse an toan.
