# US-21 - Nhân bản nội dung

## 1. User Story

**Là** người dùng,  
**tôi muốn** clone một content đã có,  
**để** tái sử dụng nhanh cho chiến dịch mới mà không phải tạo lại từ đầu.

---

## 2. Mục tiêu

Cho phép người dùng tạo một bản sao của content hiện có trong cùng profile. Bản sao được tạo với trạng thái `Draft`, giữ nguyên toàn bộ nội dung gốc, cho phép chỉnh sửa độc lập mà không ảnh hưởng đến bản gốc. Tính năng này rút ngắn thời gian chuẩn bị content cho chiến dịch mới bằng cách tái dụng nội dung đã được kiểm duyệt hoặc đã dùng trước đó.

---

## 3. Phạm vi

### Trong phạm vi

- Hiển thị nút/hành động "Clone" trên danh sách content và trang chi tiết content.
- Gọi API clone để tạo bản sao phía backend.
- Bản sao kế thừa đầy đủ các field: `BrandId`, `ProductId`, `AdType`, `Title`, `TextContent`, `ImageUrl`, `VideoUrl`, `StyleDescription`, `ContextDescription`, `RepresentativeCharacter`.
- Bản sao luôn được tạo với `Status = Draft`, bất kể trạng thái của bản gốc.
- Hiển thị loading state trong quá trình thực hiện.
- Sau khi clone thành công, điều hướng người dùng đến trang chi tiết/chỉnh sửa bản sao mới.
- Hiển thị thông báo thành công (toast/snackbar) và lỗi phù hợp.

### Ngoài phạm vi

- Clone content sang profile khác: không hỗ trợ.
- Clone kèm lịch sử AI generation: không sao chép.
- Clone kèm lịch đăng đã tạo: không sao chép.
- Clone kèm bài post đã publish: không sao chép.
- Đặt tên tùy chỉnh cho bản sao lúc clone: không hỗ trợ (có thể chỉnh sửa sau).
- Clone content đã bị soft-delete: backend từ chối, frontend không cần cung cấp action này cho content đã xóa.

---

## 4. Actor

- **Chính:** Người dùng đã đăng nhập và có profile đang hoạt động.
- **Phụ:** User Web App (frontend), Backend API, PostgreSQL.

---

## 5. Tiền điều kiện

- Người dùng đã đăng nhập và có JWT access token hợp lệ.
- Người dùng đã chọn active profile (`X-Profile-Id` hợp lệ).
- Content nguồn phải tồn tại, chưa bị soft-delete và thuộc profile đang active.
- Backend API và PostgreSQL đang hoạt động.

---

## 6. Luồng nghiệp vụ chính

1. Người dùng vào màn hình danh sách content hoặc trang chi tiết một content.
2. Người dùng nhấn nút **"Clone"** trên content muốn nhân bản.
3. Frontend hiển thị dialog xác nhận (tùy UX) hoặc gọi API trực tiếp.
4. Frontend gọi `POST /api/content/{contentId}/clone` kèm `Authorization` và `X-Profile-Id` header.
5. Backend xác thực JWT và profile context.
6. Backend kiểm tra content tồn tại, không bị xóa và thuộc profile.
7. Backend tạo bản sao mới với toàn bộ nội dung từ bản gốc, đặt `Status = Draft`.
8. Backend lưu bản sao và trả về `ContentResponseDto` của bản mới.
9. Frontend nhận phản hồi thành công, hiển thị toast thành công.
10. Frontend điều hướng người dùng đến trang chi tiết/chỉnh sửa của bản sao mới.

## 7. Luồng ngoại lệ

| Mã | Trường hợp | Kết quả mong đợi |
| --- | --- | --- |
| EX-01 | Content không tồn tại hoặc không thuộc profile hiện tại | Backend trả `404 Not Found`; frontend hiển thị thông báo lỗi và không điều hướng. |
| EX-02 | Content đã bị soft-delete | Backend trả `404 Not Found`; frontend không cung cấp nút Clone cho item đã xóa. |
| EX-03 | JWT hết hạn hoặc không hợp lệ | Backend trả `401 Unauthorized`; frontend chuyển hướng về màn hình đăng nhập. |
| EX-04 | `X-Profile-Id` thiếu, sai hoặc không thuộc user | Backend trả `400 Bad Request` hoặc `403 Forbidden`; frontend hiển thị lỗi. |
| EX-05 | Lỗi database hoặc timeout | Backend trả `500 Internal Server Error`; frontend hiển thị thông báo lỗi chung. |
| EX-06 | Người dùng nhấn Clone nhiều lần liên tiếp | Frontend disable nút sau lần nhấn đầu tiên trong khi chờ phản hồi, tránh gọi API trùng lặp. |

## 9. API Contract

### Endpoint

```
POST /api/content/{contentId}/clone
```

### Headers bắt buộc

```http
Authorization: Bearer <access-token>
X-Profile-Id: <owned-profile-guid>
```

### Path Parameters

| Tham số | Kiểu | Bắt buộc | Mô tả |
| --- | --- | --- | --- |
| `contentId` | `Guid` | Có | ID của content cần clone. |

### Request Body

Không có (no request body).

### Response thành công

`200 OK`

```json
{
  "success": true,
  "statusCode": 200,
  "message": "Content cloned successfully.",
  "data": {
    "id": "new-content-uuid",
    "profileId": "profile-uuid",
    "brandId": "brand-uuid",
    "brandName": "Tên thương hiệu",
    "productId": "product-uuid-or-null",
    "adType": 0,
    "title": "Tiêu đề bản gốc",
    "textContent": "Nội dung text bản gốc",
    "imageUrl": null,
    "videoUrl": null,
    "styleDescription": "Phong cách bản gốc",
    "contextDescription": "Ngữ cảnh bản gốc",
    "representativeCharacter": "Nhân vật đại diện",
    "status": 0,
    "createdAt": "2026-06-03T06:30:00Z",
    "updatedAt": "2026-06-03T06:30:00Z"
  }
}
```

> **Lưu ý:** `status = 0` tương ứng `ContentStatusEnum.Draft`.

### Response lỗi

| HTTP Status | ErrorCode | Trường hợp |
| --- | --- | --- |
| `401 Unauthorized` | — | JWT thiếu hoặc không hợp lệ. |
| `400 Bad Request` | — | `X-Profile-Id` thiếu hoặc không phải GUID hợp lệ. |
| `403 Forbidden` | — | Profile không thuộc user đang đăng nhập. |
| `404 Not Found` | — | Content không tồn tại, đã bị xóa, hoặc không thuộc profile. |
| `500 Internal Server Error` | — | Lỗi hệ thống không mong đợi. |

Ví dụ response lỗi:

```json
{
  "success": false,
  "statusCode": 404,
  "message": "Content not found.",
  "data": null
}
```

### Mapping enums

**`adType`:**

| Giá trị | Tên | Mô tả |
| --- | --- | --- |
| `0` | `TextOnly` | Chỉ văn bản |
| `1` | `ImageText` | Văn bản + hình ảnh |
| `2` | `VideoText` | Văn bản + video |

**`status`:**

| Giá trị | Tên | Mô tả |
| --- | --- | --- |
| `0` | `Draft` | Bản nháp (luôn là giá trị sau khi clone) |
| `1` | `PendingApproval` | Chờ duyệt |
| `2` | `Approved` | Đã duyệt |
| `3` | `Rejected` | Đã từ chối |
| `4` | `Published` | Đã đăng |

## 11. Acceptance Criteria

### AC-01 - Clone thành công từ content đang hoạt động

**Given** người dùng đã đăng nhập với profile hợp lệ và content tồn tại, chưa xóa  
**When** người dùng gọi clone cho content đó  
**Then** hệ thống tạo bản sao mới với UUID riêng  
**And** trả về `200 OK` kèm `ContentResponseDto` của bản sao  
**And** bản sao có `status = 0 (Draft)`, toàn bộ nội dung giống bản gốc  
**And** frontend điều hướng đến trang chi tiết bản sao mới.

### AC-02 - Clone giữ nguyên nội dung gốc

**Given** bản gốc có đầy đủ `Title`, `TextContent`, `ImageUrl`, `StyleDescription`, `AdType`  
**When** clone thành công  
**Then** bản sao chứa đầy đủ các giá trị đó  
**And** bản gốc không bị thay đổi.

### AC-03 - Bản clone luôn có trạng thái Draft

**Given** bản gốc có `Status = Published` hoặc `Status = Approved`  
**When** clone thành công  
**Then** bản sao luôn có `Status = Draft (0)`  
**And** bản gốc giữ nguyên trạng thái.

### AC-04 - Không clone content không thuộc profile

**Given** người dùng dùng `contentId` thuộc profile khác  
**When** gọi API clone  
**Then** hệ thống trả `404 Not Found`  
**And** không tạo bản sao nào.

### AC-05 - Không clone content đã bị xóa

**Given** content đã bị soft-delete (`IsDeleted = true`)  
**When** gọi API clone  
**Then** hệ thống trả `404 Not Found`  
**And** không tạo bản sao nào.

### AC-06 - Không clone khi thiếu xác thực

**Given** request thiếu JWT hoặc thiếu `X-Profile-Id`  
**When** gọi API clone  
**Then** hệ thống trả `401 Unauthorized` hoặc `400 Bad Request`  
**And** không tạo bản sao nào.

### AC-07 - Frontend disable nút Clone trong khi xử lý

**Given** người dùng đã nhấn nút Clone  
**When** API đang xử lý  
**Then** nút Clone bị disable và hiển thị loading  
**And** không gửi thêm request trùng lặp.

### AC-08 - Hiển thị thông báo lỗi phù hợp

**Given** API trả lỗi bất kỳ  
**When** frontend nhận phản hồi  
**Then** hiển thị toast/snackbar thông báo lỗi rõ ràng  
**And** không điều hướng sang trang mới.

#### API call

```typescript
// lib/api/content.ts
export async function cloneContent(contentId: string): Promise<ContentResponseDto> {
  const response = await apiClient.post<GenericResponse<ContentResponseDto>>(
    `/api/content/${contentId}/clone`
    // Không có request body
    // Header Authorization và X-Profile-Id được gắn tự động bởi apiClient interceptor
  );

  if (!response.data.success) {
    throw new Error(response.data.message ?? "Clone thất bại.");
  }

  return response.data.data!;
}
```

#### Handler và state management

```typescript
// hooks/useCloneContent.ts
export function useCloneContent() {
  const router = useRouter();
  const [isCloning, setIsCloning] = useState(false);

  const handleClone = useCallback(async (contentId: string) => {
    setIsCloning(true);
    try {
      const cloned = await cloneContent(contentId);
      toast.success("Clone thành công!");
      router.push(`/content/${cloned.id}`); // Điều hướng đến bản sao mới
    } catch (error) {
      toast.error(getErrorMessage(error));
    } finally {
      setIsCloning(false);
    }
  }, [router]);

  return { handleClone, isCloning };
}
```

#### TypeScript types (đối chiếu với `ContentResponseDto`)

```typescript
// types/content.ts
export type AdType = 0 | 1 | 2;           // TextOnly | ImageText | VideoText
export type ContentStatus = 0 | 1 | 2 | 3 | 4; // Draft | PendingApproval | Approved | Rejected | Published

export interface ContentResponseDto {
  id: string;
  profileId: string;
  brandId: string;
  brandName?: string | null;
  productId?: string | null;
  adType: AdType;
  title?: string | null;
  textContent: string;
  imageUrl?: string | null;
  videoUrl?: string | null;
  styleDescription?: string | null;
  contextDescription?: string | null;
  representativeCharacter?: string | null;
  status: ContentStatus;
  createdAt: string;   // ISO 8601 UTC string
  updatedAt: string;
}

export interface GenericResponse<T> {
  success: boolean;
  statusCode: number;
  message: string;
  data: T | null;
}
```

#### Xử lý lỗi từ API

```typescript
// utils/errorHandler.ts
export function getErrorMessage(error: unknown): string {
  if (axios.isAxiosError(error)) {
    const response = error.response?.data as GenericResponse<null>;
    if (response?.message) return response.message;
    switch (error.response?.status) {
      case 401: return "Phiên đăng nhập đã hết hạn. Vui lòng đăng nhập lại.";
      case 403: return "Bạn không có quyền thực hiện thao tác này.";
      case 404: return "Không tìm thấy nội dung hoặc nội dung đã bị xóa.";
      default:  return "Đã xảy ra lỗi. Vui lòng thử lại.";
    }
  }
  return "Đã xảy ra lỗi không xác định.";
}
```

#### UI/UX Guidelines

- Nút Clone nên hiển thị ở vị trí dễ thấy nhưng không gây nhầm với nút "Edit" hay "Delete".
- Sử dụng icon phù hợp (ví dụ: `Copy`, `Duplicate`, `ClipboardCopy`) từ thư viện icon của dự án.
- Sau khi clone thành công, điều hướng người dùng vào trang **chỉnh sửa bản sao** (`/content/{newId}/edit`) hoặc trang chi tiết (`/content/{newId}`) — thống nhất với UX pattern chung của dự án.
- Nếu clone từ danh sách, cập nhật danh sách bằng cách fetch lại hoặc thêm item mới vào đầu list (optimistic update).
- Không cần dialog xác nhận nếu thao tác có thể hoàn tác (người dùng có thể xóa bản clone sau); tuy nhiên nếu muốn thêm confirmation dialog thì phải non-blocking.
