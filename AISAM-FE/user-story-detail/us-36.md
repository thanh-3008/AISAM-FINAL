# US-36 - Nhận thông báo nội bộ

## 1. User Story

**Là** người dùng,
**tôi muốn** nhận notification nội bộ cho các sự kiện hệ thống liên quan đến workflow của mình,
**để** có thể theo dõi và phản hồi kịp thời các sự kiện quan trọng như duyệt nội dung, đăng bài, lịch trình, và gợi ý AI.

---

## 2. Mục tiêu

Cung cấp cơ chế nhận thông báo nội bộ qua notification bell icon trên global header: hiển thị unread count badge, dropdown danh sách notification gần nhất, cho phép người dùng xem nhanh nội dung thông báo và điều hướng đến trang chi tiết/ngữ cảnh tương ứng. Feature này giúp người dùng không bỏ lỡ các sự kiện workflow quan trọng.

---

## 3. Phạm vi

### Trong phạm vi

- Notification bell icon trên global header (luôn hiển thị khi đã đăng nhập và có active profile).
- Unread count badge trên bell icon (số notification chưa đọc).
- Dropdown hiển thị 5 notification gần nhất khi click bell.
- Mỗi notification item trong dropdown hiển thị: type icon, title, message preview, relative time, trạng thái read/unread.
- Click notification item → mark as read (nếu chưa đọc) + navigate đến trang notification detail.
- "Mark all as read" action từ dropdown.
- "View all notifications" link → navigate đến `/notifications`.
- Polling unread count định kỳ (mỗi 30 giây) để cập nhật badge real-time.
- Hiển thị danh sách notification type với icon và màu sắc phân biệt:
  - ApprovalNeeded (cần duyệt) → icon file-text, màu vàng/cam.
  - PostScheduled (bài đã lên lịch) → icon calendar, màu xanh.
  - PerformanceAlert (cảnh báo hiệu suất) → icon trending-down, màu đỏ.
  - AiSuggestion (gợi ý AI) → icon sparkles, màu tím.
  - SystemUpdate (cập nhật hệ thống) → icon info, màu xám/xanh dương.
- Scroll trong dropdown nếu có nhiều hơn 5 notifications.

### Ngoài phạm vi

- Trang danh sách notification đầy đủ (`/notifications`): US-37.
- Mark read cho từng notification trên trang danh sách: US-38.
- Realtime stream (WebSocket/SignalR): deferred, chỉ dùng polling.
- Email/push notification tương ứng: deferred.
- Notification preferences (bật/tắt từng loại): deferred.
- Xoá notification: BE không hỗ trợ, chỉ có soft-delete (bỏ qua trong UI).
- Dashboard summary counts: US-43.

## 4. Actor

- **Chính:** Người dùng đã đăng nhập, có profile đang active.
- **Phụ:** User Web App (frontend), Backend API (`NotificationsController`, `NotificationService`), PostgreSQL.

---

## 5. Tiền điều kiện

- Người dùng đã đăng nhập và có JWT access token hợp lệ.
- Người dùng đã chọn active profile (`X-Profile-Id` header hợp lệ).
- Backend notification API đã được triển khai và có dữ liệu notification trong DB (được sinh ra bởi các service khác: Scheduling, Content/Publish, AI, v.v.).
- `X-Profile-Id` header tự động gắn bởi fetcher (đã implement ở US-28).

## 6. Luồng nghiệp vụ chính

### 6.1 Xem notification qua bell dropdown

1. Người dùng đang ở bất kỳ trang nào trong ứng dụng.
2. Global header hiển thị bell icon với unread count badge.
3. Người dùng click bell icon.
4. Frontend gọi `GET /api/notifications?page=1&pageSize=5` để lấy 5 notification gần nhất.
5. Dropdown mở ra, hiển thị danh sách notification items.
6. Mỗi item hiển thị:
   - Icon theo type (với màu sắc tương ứng).
   - **Title** (in đậm nếu chưa đọc).
   - **Message** preview (1 dòng, truncate nếu quá dài).
   - **Time** hiển thị relative (e.g., "2 phút trước", "1 giờ trước", "Hôm qua 14:30").
   - Nền sáng hơn nếu chưa đọc, nền tối hơn nếu đã đọc.
7. Cuối dropdown có 2 actions: "Mark all as read" và "View all notifications".

### 6.2 Click vào notification item

1. Người dùng click vào một notification trong dropdown.
2. Nếu notification chưa đọc → frontend gọi `POST /api/notifications/{notificationId}/mark-read`.
3. Frontend navigate đến `/notifications` (trang danh sách US-37) và mở detail modal/sheet cho notification đó.

### 6.3 Mark all as read

1. Người dùng click "Mark all as read" trong dropdown.
2. Frontend gọi `POST /api/notifications/mark-all-read`.
3. Dropdown cập nhật: tất cả items chuyển sang trạng thái đã đọc (nền tối hơn, title không còn in đậm).
4. Unread count badge về 0.
5. Toast "Đã đánh dấu tất cả là đã đọc."

### 6.4 View all notifications

1. Người dùng click "View all notifications" trong dropdown.
2. Frontend navigate đến `/notifications` (US-37).
3. Dropdown đóng.

### 6.5 Polling cập nhật unread count

1. Khi người dùng đăng nhập và có active profile, frontend bắt đầu polling.
2. Mỗi 30 giây, gọi `GET /api/notifications/unread-count`.
3. Cập nhật badge trên bell icon.
4. Nếu có notification mới, bell icon có animation nhấp nháy nhẹ (pulse).
5. Khi dropdown đang mở, tạm dừng polling để tránh UI giật.

## 7. Luồng ngoại lệ

| Mã | Trường hợp | Kết quả mong đợi |
| --- | --- | --- |
| EX-01 | API notification lỗi/500 | Dropdown hiển thị thông báo lỗi inline "Không thể tải thông báo." + nút "Thử lại". Badge giữ nguyên giá trị cũ. |
| EX-02 | Không có notification nào | Dropdown hiển thị empty state: icon bell + "Chưa có thông báo nào." |
| EX-03 | Mark all read thất bại | Toast lỗi "Không thể đánh dấu tất cả. Vui lòng thử lại." Badge và dropdown không thay đổi. |
| EX-04 | Mark read một notification thất bại | Item giữ nguyên trạng thái chưa đọc. Toast lỗi. |
| EX-05 | Notification bị xoá (soft-delete) sau khi dropdown mở | BE trả 404; item biến mất khỏi dropdown khi refresh. |
| EX-06 | Polling bị rate-limit | Backend có thể trả 429; frontend tăng interval lên 60 giây và retry. |
| EX-07 | User chưa chọn profile | Bell icon ẩn hoặc disabled (không có X-Profile-Id). |

## 8. Quy tắc nghiệp vụ

| Mã | Quy tắc |
| --- | --- |
| BR-01 | Notification chỉ thuộc về một profile duy nhất (`ProfileId`). |
| BR-02 | Notification không thể bị xoá cứng (chỉ soft-delete `IsDeleted = true`). |
| BR-03 | Notification có `TargetId` và `TargetType` để FE có thể điều hướng đến resource liên quan (post, content, schedule). |
| BR-04 | Unread count chỉ tính notification `IsRead = false` AND `IsDeleted = false`. |
| BR-05 | Polling interval mặc định 30 giây; không nên dưới 15 giây để tránh quá tải. |
| BR-06 | Notification type là enum, BE lưu dưới dạng int; FE mapping dựa trên string value của enum name. |
| BR-07 | Notification list mặc định sắp xếp theo `CreatedAt` descending (mới nhất trước). |

## 12. Acceptance Criteria

### AC-01 - Notification bell hiển thị trên header

**Given** người dùng đã đăng nhập và có active profile
**When** vào bất kỳ trang nào trong ứng dụng
**Then** global header hiển thị bell icon
**And** badge hiển thị số notification chưa đọc (hoặc ẩn nếu 0).

### AC-02 - Click bell mở dropdown

**Given** bell icon đang hiển thị
**When** click bell
**Then** gọi `GET /api/notifications?page=1&pageSize=5`
**And** dropdown hiển thị 5 notification gần nhất
**And** mỗi item có icon, title, message, time, trạng thái read/unread.

### AC-03 - Unread count polling

**Given** người dùng đang active
**When** 30 giây trôi qua
**Then** gọi `GET /api/notifications/unread-count`
**And** cập nhật badge.

### AC-04 - Click notification item

**Given** dropdown đang mở
**When** click notification chưa đọc
**Then** gọi `POST /api/notifications/{id}/mark-read`
**And** navigate đến `/notifications`.

### AC-05 - Mark all as read

**Given** dropdown đang mở và có unread notifications
**When** click "Mark all as read"
**Then** gọi `POST /api/notifications/mark-all-read`
**And** tất cả items chuyển sang trạng thái đã đọc
**And** badge về 0.

### AC-06 - View all redirect

**Given** dropdown đang mở
**When** click "View all notifications"
**Then** navigate đến `/notifications`.

### AC-07 - Empty state

**Given** không có notification nào
**When** mở dropdown
**Then** hiển thị "Chưa có thông báo nào."

### AC-08 - Error state

**Given** API notification bị lỗi
**When** mở dropdown
**Then** hiển thị "Không thể tải thông báo." + nút "Thử lại".

### AC-09 - Notification type icons

**Given** dropdown có notification
**Then** mỗi notification hiển thị icon và màu sắc đúng theo type (ApprovalNeeded, PostScheduled, PerformanceAlert, AiSuggestion, SystemUpdate).

> **Lưu ý:** Backend đã implement đầy đủ:
> - `NotificationsController` — `GET /api/notifications` (paged), `GET /api/notifications/{id}`, `POST /api/notifications/{id}/mark-read`, `POST /api/notifications/mark-all-read`, `GET /api/notifications/unread-count`.

#### API Layer (notification-api.ts)

```typescript
import { apiRequest } from "@/lib/api/fetcher";
import type {
  NotificationListItemDto,
  UnreadNotificationCountDto,
  PagedResult,
} from "@/features/notifications/types/notification";

export const notificationApi = {
  getPaged: (page = 1, pageSize = 5) =>
    apiRequest<PagedResult<NotificationListItemDto>>(
      `/api/notifications?page=${page}&pageSize=${pageSize}`,
      { method: "GET", auth: true }
    ),

  getUnreadCount: () =>
    apiRequest<UnreadNotificationCountDto>("/api/notifications/unread-count", {
      method: "GET",
      auth: true,
    }),

  markRead: (notificationId: string) =>
    apiRequest<boolean>(`/api/notifications/${notificationId}/mark-read`, {
      method: "POST",
      auth: true,
    }),

  markAllRead: () =>
    apiRequest<boolean>("/api/notifications/mark-all-read", {
      method: "POST",
      auth: true,
    }),
};
```

#### Hooks

**useNotifications (dropdown):**

```typescript
// hooks/use-notifications.ts
import { useQuery, useQueryClient } from "@tanstack/react-query";
import { notificationApi } from "@/features/notifications/api/notification-api";
import { useEffect, useRef } from "react";

const POLL_INTERVAL = 30_000; // 30 giây

export function useRecentNotifications() {
  return useQuery({
    queryKey: ["notifications", "recent"],
    queryFn: () => notificationApi.getPaged(1, 5),
    staleTime: 10_000,
  });
}

export function useUnreadCount() {
  const queryClient = useQueryClient();
  const query = useQuery({
    queryKey: ["notifications", "unread-count"],
    queryFn: notificationApi.getUnreadCount,
    refetchInterval: POLL_INTERVAL,
    staleTime: POLL_INTERVAL,
  });

  // Pulse animation trigger khi count tăng
  const prevCountRef = useRef(query.data?.count ?? 0);
  const hasNewNotification =
    (query.data?.count ?? 0) > prevCountRef.current;

  useEffect(() => {
    if (query.data) {
      prevCountRef.current = query.data.count;
    }
  }, [query.data]);

  return { ...query, hasNewNotification };
}
```

**useNotificationActions:**

```typescript
// hooks/use-notification-actions.ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { notificationApi } from "@/features/notifications/api/notification-api";
import { useToastStore } from "@/stores/toast-store";

export function useMarkRead() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (notificationId: string) =>
      notificationApi.markRead(notificationId),
    onSuccess: () => {
      void queryClient.invalidateQueries({ queryKey: ["notifications"] });
    },
  });
}

export function useMarkAllRead() {
  const queryClient = useQueryClient();
  const toast = useToastStore((s) => s.push);
  return useMutation({
    mutationFn: notificationApi.markAllRead,
    onSuccess: () => {
      void queryClient.invalidateQueries({ queryKey: ["notifications"] });
      toast({ title: "Đã đánh dấu tất cả là đã đọc.", tone: "success" });
    },
    onError: () => {
      toast({ title: "Không thể đánh dấu tất cả. Vui lòng thử lại.", tone: "error" });
    },
  });
}
```

      if (dropdownRef.current && !dropdownRef.current.contains(e.target as Node)) {
        setIsOpen(false);
      }
    };
    document.addEventListener("mousedown", handleClickOutside);
    return () => document.removeEventListener("mousedown", handleClickOutside);
  }, []);

  return (
    <div ref={dropdownRef} className="relative">
      <button
        onClick={() => setIsOpen(!isOpen)}
        className="relative rounded-full p-2 transition-colors hover:bg-muted"
        aria-label={`Notifications (${unreadCount} unread)`}
      >
        <Bell
          className={`h-5 w-5 ${hasNewNotification ? "animate-pulse" : ""}`}
        />
        {unreadCount > 0 && (
          <span className="absolute -right-0.5 -top-0.5 flex h-4 min-w-[16px] items-center justify-center rounded-full bg-red-500 px-1 text-[10px] font-bold text-white">
            {unreadCount > 99 ? "99+" : unreadCount}
          </span>
        )}
      </button>

      {isOpen && (
        <div className="absolute right-0 z-50 mt-2 w-80 rounded-2xl border bg-card shadow-2xl">
          <NotificationDropdown onClose={() => setIsOpen(false)} />
        </div>
      )}
    </div>
  );
}

function NotificationItem({
  notification,

  notification: NotificationListItemDto;

          }`}

        </p>

function formatRelativeTime(dateStr: string): string {
  const now = Date.now();
  const date = new Date(dateStr).getTime();
  const diffMs = now - date;
  const diffMins = Math.floor(diffMs / 60_000);
  const diffHours = Math.floor(diffMs / 3_600_000);
  const diffDays = Math.floor(diffMs / 86_400_000);

  if (diffMins < 1) return "Vừa xong";
  if (diffMins < 60) return `${diffMins} phút trước`;
  if (diffHours < 24) return `${diffHours} giờ trước`;
  if (diffDays < 7) return `${diffDays} ngày trước`;

  return new Intl.DateTimeFormat("vi-VN", {
    month: "short",
    day: "numeric",
    hour: "2-digit",
    minute: "2-digit",
  }).format(new Date(dateStr));
}

  TrendingDown: TrendingDown,
  Sparkles: Sparkles,
  Info: Info,
  Bell: Bell,
  BellOff: BellOff,
};
