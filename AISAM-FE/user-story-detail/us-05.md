# US-05 Frontend Detail - Dang xuat phien hien tai

## 1. User story

La nguoi dung da dang nhap, toi muon dang xuat de ket thuc phien su dung hien tai mot cach an toan.

## 2. Muc tieu frontend

- Cung cap thao tac logout ro rang trong app.
- Goi dung endpoint logout cua backend.
- Xoa session phia frontend du backend thanh cong hay that bai.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `requirement.md` muc `6.1` yeu cau he thong ho tro dang xuat.

### Backend plan lien quan

- `BACKEND_CODE_PLAN.md` Phase 3 yeu cau `logout`.

### Backend implementation thuc te

- Endpoint: `POST /api/Auth/logout`
- Authorization: bat buoc
- Request body:
  - `refreshToken` co the co hoac khong
- Response: `GenericResponse<object>` voi `data = null`

### Hanh vi backend can frontend phai follow

- Neu frontend gui `refreshToken`, backend se revoke dung session do neu no thuoc ve user
- Neu khong gui `refreshToken`, backend khong revoke session nao, nhung request van tra `200`
- Backend khong tra thong tin session sau logout

## 4. Pham vi frontend

### Trong pham vi

- Nut/menu logout
- Goi API logout
- Xoa auth state
- Xoa active profile state
- Redirect ve `/login`

### Ngoai pham vi

- Dang xuat tat ca thiet bi: thuoc `US-06`

## 5. API contract can dung

### Request

`POST /api/Auth/logout`

Header:

```http
Authorization: Bearer <accessToken>
```

Body de xuat frontend gui:

```json
{
  "refreshToken": "current-refresh-token"
}
```

### Success response

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "Logout successful",
  "statusCode": 200,
  "data": null,
  "error": null
}
```

### Error response

- `500` khi loi he thong
- `401` co the xay ra neu access token da khong hop le truoc khi toi controller

## 6. UI/UX spec

### Vi tri thao tac

- User menu
- Sidebar/header account menu

### Confirmation

- Co the logout truc tiep khong can confirm modal
- Neu dung modal, text phai ngan gon

## 7. Validation frontend

- Chi hien logout cho user da authenticated
- Neu co `refreshToken` trong auth store thi gui len backend

## 8. Data flow frontend

1. User bam `Logout`
2. Frontend goi `POST /api/Auth/logout`
3. Du backend thanh cong hay loi:
   - clear auth store
   - clear active profile store
   - xoa persisted session
   - redirect `/login`

## 9. State can xu ly

### Loading state

- Disable nut logout trong luc request dang chay

### Success state

- User ve trang login

### Failure state

- Neu API loi, frontend van xoa session local
- Co the hien toast `Logged out locally`

## 10. Auth/session impact

- Auth store phai bi clear hoan toan
- Active profile phai bi clear
- Query cache cho protected data nen duoc reset/clear neu architecture dang su dung TanStack Query

## 11. Dieu huong sau dang xuat

- Redirect: `/login`

## 12. Acceptance criteria

### AC-01

Khi user bam logout, frontend goi dung endpoint `POST /api/Auth/logout`.

### AC-02

Frontend gui `refreshToken` hien tai neu dang co trong auth store.

### AC-03

Sau logout, frontend xoa session va dua user ve `/login`.

### AC-04

Ngay ca khi API logout loi, frontend van khong giu user o trang protected bang session cu.

## 13. Test cases frontend

### FE-01

Click logout goi API voi bearer token va refresh token.

### FE-02

Logout thanh cong se clear auth store va active profile store.

### FE-03

Logout API fail van redirect `/login` va clear session local.

## 14. Ghi chu implementation

- Neu frontend khong gui `refreshToken`, backend se khong revoke current refresh session; vi vay frontend nen gui.
- Khong can cho logout thanh cong moi clear local state.
- Story nay can duoc wired voi navigation shell, khong chi page account.
