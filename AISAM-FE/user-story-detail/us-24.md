# US-24 - Phê duyệt kết quả AI để cập nhật content

## 1. User Story

**Là** người dùng,
**tôi muốn** chọn một AI generation phù hợp và áp dụng nó vào content chính,
**để** có nội dung tốt nhất trước khi tiếp tục chỉnh sửa, schedule hoặc publish.

---

## 2. Mục tiêu

Cho phép người dùng xem tất cả các phiên bản AI generation đã tạo cho một content (từ generate-draft, improve), so sánh chúng với nhau, chọn phiên bản ưng ý nhất, và phê duyệt (approve) để cập nhật `TextContent` của content. Ngoài ra hỗ trợ reject generation không phù hợp (soft-delete) để giữ danh sách gọn gàng. Feature này giúp người dùng kiểm soát chất lượng nội dung và đảm bảo chỉ áp dụng phiên bản tốt nhất vào content chính.

---

## 3. Phạm vi

### Trong phạm vi

- Màn hình / panel "Generation Review" hiển thị danh sách tất cả AI generations của một content.
- Xem chi tiết từng generation: prompt, generated text, status, timestamp, error message (nếu failed).
- So sánh hai generation cạnh nhau (side-by-side diff) hoặc so với content hiện tại.
- Chọn một generation và Approve để cập nhật `TextContent` của content.
- Gọi API `POST /api/ai/approve/{aiGenerationId}` khi approve.
- Gọi API `GET /api/ai/generations/{contentId}` để load danh sách.
- Highlight generation đã được approve trước đó (nếu có).
- Toast thông báo thành công / lỗi khi approve.
- Loading state, disable button khi đang xử lý.

### Ngoài phạm vi

- Generate draft mới (US-22).
- Improve content (US-23).
- Chat refinement với AI (US-22).
- Reject generation: backend chưa có endpoint reject/delete generation; cần implement riêng nếu required.
- Batch approve nhiều generation cùng lúc.
- Auto-approve generation theo rule.
- Version history rollback (quay lại generation cũ sau khi đã approve cái khác).
- Export generation text ra file.

## 4. Actor

- **Chính:** Người dùng đã đăng nhập, có profile đang active, có content với ít nhất một AI generation.
- **Phụ:** User Web App (frontend), Backend API (GeminiController/AIService), PostgreSQL.

---

## 5. Tiền điều kiện

- Người dùng đã đăng nhập và có JWT access token hợp lệ.
- Người dùng đã chọn active profile (`X-Profile-Id` header hợp lệ).
- Content tồn tại, chưa bị soft-delete và thuộc profile đang active.
- Content có ít nhất một `AiGeneration` (từ generate-draft hoặc improve).

## 6. Luồng nghiệp vụ chính

### 6.1 Xem danh sách tất cả generations của content

1. Người dùng truy cập màn hình Generation Review từ:
   - **Nút "View Generations" / "Review"** trên trang chi tiết content (`/content/{contentId}`).
   - **Tab "Generation History"** trong màn hình AI Generation (`/ai`) khi đã chọn content.
2. Frontend gọi `GET /api/ai/generations/{contentId}`.
3. Hệ thống hiển thị danh sách tất cả generations của content, sắp xếp mới nhất trước.
4. Mỗi item trong danh sách hiển thị:
   - **Status badge**: `Completed` (xanh), `Failed` (đỏ), `Pending` (vàng).
   - **Prompt** (rút gọn, có tooltip đầy đủ).
   - **Generated text** (preview 2-3 dòng, có nút "Xem thêm").
   - **Timestamp** (`CreatedAt`).
   - **Badge "Current"** nếu generation này đã được approve trước đó và đang là `TextContent` hiện tại.
   - Nút **"Approve"** (chỉ hiển thị nếu generation `Completed` và chưa được approve).

### 6.2 Xem chi tiết và so sánh generation

1. Người dùng click vào một generation item để xem chi tiết.
2. Hệ thống mở panel/xem chi tiết với:
   - **Prompt** đầy đủ (read-only).
   - **Generated text** (full, với syntax highlight nếu cần).
   - **Status và timestamp**.
   - **Error message** (nếu Failed).
3. Người dùng có thể chọn **"So sánh với content hiện tại"**:
   - Hiển thị side-by-side: bên trái là `Content.TextContent` hiện tại, bên phải là `GeneratedText`.
   - Highlight khác biệt (thêm/xoá).

### 6.3 Approve generation

1. Người dùng chọn một generation `Completed` và nhấn nút **"Approve"**.
2. Frontend hiển thị dialog xác nhận:
   - "Bạn có chắc chắn muốn áp dụng generation này? Nội dung hiện tại sẽ được thay thế."
   - Nếu đã có generation khác được approve trước đó, hiển thị cảnh báo: "Nội dung hiện tại sẽ bị thay thế. Bạn có thể xem lại generation cũ trong lịch sử."
3. Người dùng xác nhận.
4. Frontend gọi `POST /api/ai/approve/{aiGenerationId}`.
5. Backend validate: generation tồn tại, thuộc profile, status `Completed`, `GeneratedText` không rỗng.
6. Backend copy `GeneratedText` vào `Content.TextContent`, giữ `Status = Draft`.
7. Frontend nhận response `ContentResponseDto`:
   - Hiển thị toast "Approved thành công!".
   - Đánh dấu generation này là "Current" trong danh sách (badge).
   - Cập nhật `textContent` hiển thị trong page (nếu ở content detail).
   - Bỏ badge "Current" khỏi generation cũ (nếu có).

### 6.4 Generation History tab trong AI page (tích hợp US-22)

1. Người dùng đang ở màn hình AI Generation (`/ai`), sau khi generate hoặc improve.
2. Tab "Generation History" hiển thị danh sách generations của content hiện tại.
3. Từ tab này, người dùng có thể:
   - **Approve** một generation cũ (nếu Completed).
   - **So sánh** với content hiện tại.
   - **Improve** dựa trên generation đã chọn (điều hướng đến US-23).

## 7. Luồng ngoại lệ

| Mã | Trường hợp | Kết quả mong đợi |
| --- | --- | --- |
| EX-01 | Content không tồn tại hoặc không thuộc profile | Backend trả `404 Not Found`; frontend hiển thị lỗi và không load danh sách. |
| EX-02 | Content không có generation nào | Hiển thị empty state: "Chưa có generation nào. Hãy tạo generation mới." kèm link/nút đến AI Generation. |
| EX-03 | Generation không tồn tại khi approve | Backend trả `404 Not Found`; frontend hiển thị lỗi. |
| EX-04 | Generation không thuộc profile khi approve | Backend trả `404 Not Found`; frontend hiển thị lỗi. |
| EX-05 | Generation chưa hoàn thành (Pending/Failed) khi approve | Backend trả `400 Bad Request`; frontend disable nút Approve nếu generation không phải Completed. |
| EX-06 | Generation đã được approve trước đó (không idempotent) | Mỗi lần approve đều ghi đè `TextContent` mới; frontend hiển thị cảnh báo trước khi approve lần nữa. |
| EX-07 | JWT hết hạn hoặc không hợp lệ | Backend trả `401 Unauthorized`; frontend tự động refresh token hoặc chuyển hướng đăng nhập. |
| EX-08 | X-Profile-Id thiếu hoặc không thuộc user | Backend trả `400 Bad Request` / `403 Forbidden`; frontend hiển thị lỗi. |
| EX-09 | Người dùng nhấn Approve nhiều lần | Frontend disable nút sau lần nhấn đầu tiên đến khi có phản hồi. |
| EX-10 | Không có generation `Completed` nào | Ẩn hoặc disable nút Approve trên toàn bộ danh sách; hiển thị thông báo "Chưa có generation nào hoàn thành." |
| EX-11 | Lỗi mạng khi load generation list | Toast "Không thể tải danh sách generation. Vui lòng thử lại."; nút Retry. |

## 8. Quy tắc nghiệp vụ

| Mã | Quy tắc |
| --- | --- |
| BR-01 | `ProfileId` được lấy từ `X-Profile-Id` header đã được middleware validate, không lấy từ request body. |
| BR-02 | Chỉ generation có `Status == Completed` và `GeneratedText` không rỗng mới được approve. |
| BR-03 | Approve sẽ copy `GeneratedText` vào `Content.TextContent`; content vẫn giữ `Status = Draft`. |
| BR-04 | Approve KHÔNG thay đổi `Content.Status`. Content vẫn ở trạng thái `Draft` để người dùng tiếp tục chỉnh sửa. |
| BR-05 | Mỗi lần approve ghi đè `TextContent` hiện tại; không lưu version history của content (generation cũ vẫn còn trong bảng `AiGeneration`). |
| BR-06 | Thứ tự hiển thị generation list: mới nhất trước (descending by `CreatedAt`). |
| BR-07 | Generation đã approve trước đó không có trường đánh dấu riêng; frontend tự xác định bằng cách so sánh `AiGeneration.GeneratedText == Content.TextContent` hoặc lưu `approvedGenerationId` trong state. |
| BR-08 | Không thể approve generation của content thuộc profile khác. |
| BR-09 | Approve không idempotent: approve cùng generation hai lần vẫn ghi đè `TextContent` giống nhau. |

## 9. API Contracts

```
GET /api/ai/generations/{contentId}
```

#### Headers bắt buộc

```http
Authorization: Bearer <access-token>
X-Profile-Id: <owned-profile-guid>
```

#### Path Parameters

| Tham số | Kiểu | Bắt buộc | Mô tả |
| --- | --- | --- | --- |

### 9.2 Approve Generation

```
POST /api/ai/approve/{aiGenerationId}
```

#### Headers

```http
Authorization: Bearer <access-token>
X-Profile-Id: <owned-profile-guid>
```

#### Path Parameters

| Tham số | Kiểu | Bắt buộc | Mô tả |
| --- | --- | --- | --- |
| `aiGenerationId` | `Guid` | Có | ID của AI generation cần approve. |

#### Request Body

Không có (no body).

#### Response thành công (`200 OK`)

```json
{
  "success": true,
  "statusCode": 200,
  "message": "AI generation approved.",
  "data": {
    "id": "content-uuid",
    "profileId": "profile-uuid",
    "brandId": "brand-uuid",
    "brandName": "Brand Name",
    "productId": null,
    "adType": 0,
    "title": "Summer campaign draft",
    "textContent": "🔥 Best version with emojis and urgency!",
    "imageUrl": null,
    "videoUrl": null,
    "styleDescription": null,
    "contextDescription": null,
    "representativeCharacter": null,
    "status": 0,
    "createdAt": "2026-06-03T06:30:00Z",
    "updatedAt": "2026-06-03T06:41:00Z"
  }

```

#### Response lỗi

| HTTP Status | errorCode | Trường hợp |
| --- | --- | --- |
| `401 Unauthorized` | — | JWT thiếu hoặc không hợp lệ. |
| `400 Bad Request` | — | Generation chưa hoàn thành (Pending/Failed). |
| `403 Forbidden` | — | Profile không thuộc user đang đăng nhập. |
| `404 Not Found` | — | Generation không tồn tại, đã bị xóa, hoặc không thuộc profile. |
| `500 Internal Server Error` | — | Lỗi hệ thống không mong đợi. |

## 12. Acceptance Criteria

### AC-01 - Xem danh sách generations của content

**Given** content có ít nhất một AI generation
**When** người dùng mở màn hình Generation Review
**Then** `GET /api/ai/generations/{contentId}` được gọi
**And** danh sách generation hiển thị theo thứ tự mới nhất trước
**And** mỗi card hiển thị status, prompt, generated text preview, timestamp.

### AC-02 - Approve generation thành công

**Given** generation có `Status = Completed` và `GeneratedText` không rỗng
**When** người dùng nhấn Approve và xác nhận
**Then** `POST /api/ai/approve/{aiGenerationId}` được gọi
**And** frontend hiển thị toast "Approved thành công!"
**And** generation được đánh dấu "Current" trong danh sách
**And** content `TextContent` được cập nhật.

### AC-03 - Approve generation thất bại khi generation không Completed

**Given** generation có `Status = Pending` hoặc `Failed`
**When** hiển thị generation card
**Then** nút Approve bị disabled hoặc ẩn.

### AC-04 - Approve generation không tồn tại

**Given** aiGenerationId không hợp lệ
**When** gọi Approve API
**Then** backend trả `404 Not Found`
**And** frontend hiển thị thông báo lỗi.

### AC-05 - So sánh generation với content hiện tại

**Given** generation đã được chọn
**When** người dùng nhấn "Compare"
**Then** hiển thị side-by-side: content hiện tại và generated text
**And** highlight khác biệt giữa hai bên.

### AC-06 - Xác nhận trước khi approve

**Given** người dùng nhấn Approve
**When** generation khác với content hiện tại
**Then** hiển thị dialog xác nhận: "Bạn có chắc chắn muốn áp dụng generation này?"
**And** chỉ gọi API sau khi người dùng xác nhận.

### AC-07 - Disable nút Approve khi đang xử lý

**Given** người dùng đã nhấn Approve
**When** API đang xử lý
**Then** nút Approve bị disable và hiển thị spinner
**And** không gửi request thứ hai.

### AC-08 - Highlight generation đã approve trước đó

**Given** content đã có `TextContent` khớp với một generation
**When** load generation list
**Then** generation đó hiển thị badge "Current" và nút "Approved ✓" (disabled).

### AC-09 - Content không có generation

**Given** content chưa có AI generation nào
**When** người dùng mở màn hình Generation Review
**Then** hiển thị empty state với hướng dẫn tạo generation mới.

### AC-10 - Generation Failed hiển thị error message

**Given** generation có `Status = Failed`
**When** hiển thị trong danh sách
**Then** hiển thị icon ❌, badge "Failed", và `ErrorMessage` bên dưới
**And** nút Approve không hiển thị.

### AC-11 - Generation Pending hiển thị trạng thái chờ

**Given** generation có `Status = Pending`
**When** hiển thị trong danh sách
**Then** hiển thị icon ⏳, badge "Pending"
**And** nút Approve không hiển thị.

// hooks/useApproveGeneration.ts
function useApproveGeneration() {
  const [isApproving, setIsApproving] = useState(false);
  const [confirmDialog, setConfirmDialog] = useState<{
    generationId: string;
    generationText: string;
  } | null>(null);

  const handleApprove = async (generationId: string) => {
    setIsApproving(true);
    try {
      const result = await aiApi.approve(generationId);
      if (result.success) {
        toast.success("Approved thành công!");
        // Refresh generation list
        // Update current content text
      } else {
        toast.error(result.message ?? "Không thể approve.");
      }
    } catch (error) {
      toast.error("Không thể approve. Vui lòng thử lại.");
    } finally {
      setIsApproving(false);
    }
  };

  const requestApprove = (generationId: string, generationText: string) => {
    // Show confirmation dialog first
    setConfirmDialog({ generationId, generationText });
  };

  return { isApproving, confirmDialog, requestApprove, handleApprove, setConfirmDialog };
}
