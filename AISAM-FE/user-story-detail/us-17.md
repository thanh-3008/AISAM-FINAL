# US-17 Frontend Detail - Quan ly san pham theo brand

## 1. User story

La nguoi dung da dang nhap, da chon business profile va brand, toi muon tao, xem, cap nhat, xoa va khoi phuc san pham theo tung brand de quan ly du lieu quang cao.

## 2. Muc tieu frontend

- Cung cap man hinh quan ly product catalog theo brand.
- Goi dung Product API MVP dang active trong backend.
- Dam bao frontend chi hien thi va thao tac product thuoc brand ma user so huu.
- Tao du lieu product lam context cho Content va AI generation.
- Xu ly dung gioi han MVP: product image upload chua duoc backend bat.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `requirement.md` muc `6.4 Product Catalog` yeu cau them, sua, xoa san pham theo tung brand.
- Product can luu ten, mo ta, gia, selling points chinh va anh san pham trong pham vi MVP.
- Backend MVP hien tai co field `Name`, `Description`, `Price`, `Images`, nhung upload anh qua `ImageFiles` dang bi service tu choi.

### Backend plan lien quan

- `BACKEND_CODE_PLAN.md` Phase 4 da active Profile/Brand/Product MVP.
- `CODEBASE_UPDATE.md` xac nhan ProductController/ProductService/ProductRepository da co trong active backend.
- Task 4.3 ghi ro Product API duoc bao ve bang JWT va kiem tra user la owner cua Brand/Profile.

### Backend implementation thuc te

- Controller: `AISAM-BE/AISAM.API/Controllers/ProductController.cs`
- Service: `AISAM-BE/AISAM.Services/Service/ProductService.cs`
- Repository: `AISAM-BE/AISAM.Repositories/Repository/ProductRepository.cs`
- DTO:
  - `ProductCreateRequest`
  - `ProductUpdateRequestDto`
  - `ProductResponseDto`
- Authorization: bat buoc JWT.
- Create/update dung `multipart/form-data`, khong phai JSON.
- Response list: `GenericResponse<PagedResult<ProductResponseDto>>`
- Response detail/create/update: `GenericResponse<ProductResponseDto>`
- Response delete/restore: `GenericResponse<bool>`

### Hanh vi backend can frontend phai follow

- Tat ca endpoint product can `Authorization: Bearer <accessToken>`.
- List product co the loc theo `brandId` query.
- Neu co `brandId`, backend validate brand thuoc user dang dang nhap.
- Neu khong co `brandId`, backend tra product cua cac brand ma user so huu, nhung frontend story nay nen mac dinh scope theo brand dang chon.
- Create product bat buoc gui `BrandId` trong form-data.
- Update product co the gui `BrandId` neu cho phep chuyen product sang brand khac ma user so huu.
- Delete la soft delete.
- Restore chi thanh cong khi product dang bi soft delete.
- `GET /api/products/{id}` hien tai chi lay product chua bi xoa.
- Muon xem product da xoa de restore, frontend dung list voi `includeDeleted=true`.
- Neu gui `ImageFiles`, backend tra loi: `Product image upload is not enabled in the current MVP backend.`

## 4. Pham vi frontend

### Trong pham vi

- Trang product catalog theo brand.
- Chon brand trong active profile truoc khi quan ly product.
- List product theo `brandId`.
- Search, sort, pagination theo API.
- Tao product.
- Xem chi tiet product.
- Cap nhat product.
- Xoa mem product.
- Xem danh sach product da xoa va khoi phuc.
- Dong bo cache/state sau create/update/delete/restore.
- Chan upload image file trong MVP hoac hien thong bao tinh nang chua ho tro.

### Ngoai pham vi

- Upload anh product qua storage service.
- Quan ly thu vien media.
- Multi-image editor.
- Inventory/SKU/stock.
- Category/tag product.
- Selling points field rieng neu backend chua co schema.
- Product analytics.
- Product shared qua team permission.

## 5. API contract can dung

### List request

`GET /api/products?brandId={brandId}&page=1&pageSize=10&searchTerm=&sortBy=&sortDescending=true&includeDeleted=false`

Header:

```http
Authorization: Bearer <accessToken>
X-Profile-Id: <activeProfileId>
```

Query params:

- `brandId` optional tren backend, nhung required trong UI story nay khi quan ly theo brand.
- `page` optional, default `1`
- `pageSize` optional, default `10`, backend clamp toi da `100`
- `searchTerm` optional, search theo `name` va `description`
- `sortBy` optional:
  - `name`
  - `price`
  - `createdAt`
- `sortDescending` optional, default `true`
- `includeDeleted` optional, default `false`

### Detail request

`GET /api/products/{id}`

Header:

```http
Authorization: Bearer <accessToken>
X-Profile-Id: <activeProfileId>
```

### Create request

`POST /api/products`

Header:

```http
Authorization: Bearer <accessToken>
X-Profile-Id: <activeProfileId>
Content-Type: multipart/form-data
```

Form-data:

| Field | Required | Ghi chu |
| --- | --- | --- |
| `BrandId` | Yes | Lay tu brand dang chon. |
| `Name` | Yes | Toi da 255 ky tu. |
| `Description` | No | Toi da 2000 ky tu. |
| `Price` | No | Decimal, nen >= 0 o frontend. |
| `ImageFiles` | No | Khong gui trong MVP vi backend chua bat upload. |

Vi du logical payload:

```text
BrandId=brand-guid
Name=Ca phe rang moc 250g
Description=Huong chocolate nhe, phu hop pha phin va cold brew
Price=149000
```

### Update request

`PUT /api/products/{id}`

Header:

```http
Authorization: Bearer <accessToken>
X-Profile-Id: <activeProfileId>
Content-Type: multipart/form-data
```

Form-data fields deu optional:

| Field | Ghi chu |
| --- | --- |
| `BrandId` | Chi gui neu UI cho phep chuyen product sang brand khac cung active profile. |
| `Name` | Ten moi. |
| `Description` | Mo ta moi. |
| `Price` | Gia moi. |
| `ImageFiles` | Khong gui trong MVP. |

### Delete request

`DELETE /api/products/{id}`

Header:

```http
Authorization: Bearer <accessToken>
X-Profile-Id: <activeProfileId>
```

### Restore request

`POST /api/products/{id}/restore`

Header:

```http
Authorization: Bearer <accessToken>
X-Profile-Id: <activeProfileId>
```

### Success response list

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "Products retrieved successfully",
  "statusCode": 200,
  "data": {
    "data": [
      {
        "id": "product-guid",
        "brandId": "brand-guid",
        "name": "Ca phe rang moc 250g",
        "description": "Huong chocolate nhe, phu hop pha phin va cold brew",
        "price": 149000,
        "images": [],
        "createdAt": "2026-06-03T00:00:00Z",
        "updatedAt": "2026-06-03T00:00:00Z"
      }
    ],
    "totalCount": 1,
    "page": 1,
    "pageSize": 10
  },
  "error": null
}
```

### Success response create/update/detail

HTTP:

- Create: `201 Created`
- Detail/update: `200 OK`

```json
{
  "success": true,
  "message": "Product created successfully",
  "statusCode": 200,
  "data": {
    "id": "product-guid",
    "brandId": "brand-guid",
    "name": "Ca phe rang moc 250g",
    "description": "Huong chocolate nhe, phu hop pha phin va cold brew",
    "price": 149000,
    "images": [],
    "createdAt": "2026-06-03T00:00:00Z",
    "updatedAt": "2026-06-03T00:00:00Z"
  },
  "error": null
}
```

### Success response delete/restore

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "Product deleted successfully",
  "statusCode": 200,
  "data": true,
  "error": null
}
```

### Error response can xu ly

- `401` neu chua dang nhap hoac token khong hop le.
- `400` voi cac loi:
  - `Brand not found`
  - `You are not allowed to access this brand`
  - `You are not allowed to access this product`
  - `You are not allowed to update this product`
  - `You are not allowed to delete this product`
  - `You are not allowed to restore this product`
  - `Product image upload is not enabled in the current MVP backend.`
  - `Product is not deleted`
- `404` voi detail/delete product khong ton tai hoac khong con active.
- `500` neu loi he thong.

## 6. UI/UX spec

### Route de xuat

- `/products`
- Hoac `/brand/{brandId}/products` neu router hien tai da co brand detail.

### Thanh phan can co

- Header/module title gan voi active profile va selected brand.
- Brand selector chi hien brand thuoc active profile.
- Search input.
- Sort control theo `createdAt`, `name`, `price`.
- Toggle/tab:
  - active products
  - deleted products
- Product list dang table hoac card compact.
- Nut `Create product`.
- Row/card actions:
  - view detail
  - edit
  - delete
  - restore neu dang o deleted view
- Dialog/page form tao va sua product.
- Confirm dialog truoc khi delete.

### Form fields

1. `name`
   - required
2. `description`
   - optional
3. `price`
   - optional
4. `brandId`
   - lay tu brand dang chon
   - create: khong cho user sua trong form neu da vao tu brand detail
   - update: chi cho chuyen brand neu UI co selector brand cung active profile

### Khong hien thi trong MVP nhu field luu chinh thuc

- Upload image file.
- Product gallery editor.
- Selling points field rieng.
- SKU, stock, category.

Neu can hien image, chi render `images` tu response. Backend hien tai create product moi se tra `images: []` neu khong co upload.

### Empty state

- Chua co active profile:
  - hien CTA chon hoac tao business profile.
- Da co active profile nhung chua co brand:
  - hien CTA tao brand truoc.
- Da chon brand nhung chua co product:
  - hien CTA `Create product`.
- Deleted view chua co product:
  - hien empty state nhe, khong can CTA tao moi.

## 7. Validation frontend

- `brandId` required va phai thuoc active profile.
- `name` required.
- `name` toi da `255` ky tu.
- `description` toi da `2000` ky tu.
- `price` optional, neu co thi phai la so decimal hop le va nen >= 0.
- Khong cho submit create neu chua co active profile hoac chua chon brand.
- Khong gui `ImageFiles` trong MVP.
- Neu nguoi dung paste/nhap image file o UI tuong lai, hien message tinh nang upload anh chua ho tro.

## 8. Data flow frontend

1. User vao trang product.
2. Frontend kiem tra auth session va active profile.
3. Neu chua co active profile:
   - hien blocking state yeu cau chon profile.
4. Neu da co active profile:
   - load brand list theo `US-15/US-16`.
5. User chon mot brand.
6. Frontend goi `GET /api/products?brandId={brandId}`.
7. User search/sort/page:
   - goi lai list voi query tuong ung.
8. User tao product:
   - build `FormData`
   - append `BrandId`, `Name`, `Description`, `Price`
   - khong append `ImageFiles`
   - submit `POST /api/products`
   - invalidate/refetch product list cua brand.
9. User sua product:
   - co the dung data tren list hoac goi detail `GET /api/products/{id}`
   - submit `PUT /api/products/{id}` bang `FormData`
   - invalidate/refetch list va detail.
10. User xoa product:
   - confirm
   - goi `DELETE /api/products/{id}`
   - refetch active list va deleted list neu dang co cache.
11. User khoi phuc product:
   - chuyen sang deleted view hoac list voi `includeDeleted=true`
   - goi `POST /api/products/{id}/restore`
   - refetch list.

## 9. State can xu ly

### Loading state

- loading brand selector.
- loading product list ban dau.
- loading search/page/sort.
- loading create/update/delete/restore action.

### Success state

- toast/banner khi tao, cap nhat, xoa, khoi phuc thanh cong.
- list cap nhat dung sau mutation.

### Error state

- chua dang nhap.
- chua chon active profile.
- active profile chua co brand.
- chua chon brand.
- brand khong ton tai.
- khong co quyen truy cap brand/product.
- product khong ton tai.
- upload image chua ho tro.
- validation error tu backend.
- generic server error.

## 10. Auth/profile/brand impact

- Khong doi auth session.
- Bat buoc co active profile tu `profile-store`.
- Bat buoc co selected brand thuoc active profile.
- Product API hien tai khong nam trong `ActiveProfileMiddleware`, nhung fetcher chung nen gui `X-Profile-Id` de thong nhat voi cac module khac.
- Khi active profile thay doi:
  - reset selected brand neu brand cu khong thuoc profile moi.
  - invalidate product query/cache.
  - dong form product dang mo neu dang gan brand cu.
- Khi selected brand thay doi:
  - refetch product list theo brand moi.

## 11. Dieu huong sau thao tac

- Sau create/update: o lai trang product, dong dialog/form va refetch list.
- Sau delete: o lai trang product, xoa item khoi active list.
- Sau restore: o lai deleted view hoac chuyen ve active view tuy UX, nhung phai refetch.
- Neu detail product khong thuoc brand/profile hien tai: dieu huong ve list product cua selected brand.

## 12. Acceptance criteria

### AC-01

Frontend chi load product khi user da dang nhap, co active profile va co selected brand.

### AC-02

Frontend goi list product dung endpoint `GET /api/products` voi `brandId` cua selected brand.

### AC-03

Frontend tao product bang `POST /api/products` voi `multipart/form-data` co `BrandId`, `Name`, `Description`, `Price` theo contract.

### AC-04

Frontend khong gui `ImageFiles` trong MVP va khong hien upload anh nhu chuc nang da hoan thien.

### AC-05

Frontend cap nhat product bang `PUT /api/products/{id}` voi `multipart/form-data` va dong bo lai list/detail sau khi thanh cong.

### AC-06

Frontend xoa product bang `DELETE /api/products/{id}` sau confirm va khong hien product do trong active list.

### AC-07

Frontend co cach xem product da xoa bang `includeDeleted=true` va khoi phuc bang `POST /api/products/{id}/restore`.

### AC-08

Khi backend tra ownership/brand error, frontend hien thong diep ro va khong hien product cua brand/profile khong thuoc user.

### AC-09

Khi active profile hoac selected brand thay doi, frontend reset cache/selection product cu va refetch dung scope moi.

## 14. Ghi chu implementation

- Backend create tra HTTP `201`, frontend khong duoc hardcode chi chap nhan `200`.
- Create/update product phai dung `FormData`; khong set `Content-Type: application/json`.
- Khi gui `FormData`, de browser/fetcher tu set boundary cho `multipart/form-data`.
- `ProductResponseDto` hien chua co `isDeleted`, nen khi dung `includeDeleted=true`, frontend co the can suy luan deleted view theo query/action vua thao tac hoac can backend bo sung field sau.
- Neu UI can phan biet active/deleted ro rang, nen de xuat backend bo sung `isDeleted` vao `ProductResponseDto` trong story/backend task rieng.
- `Images` hien la list string nhung MVP create/update khong them anh moi.
- Neu user can product selling points, co the tam thoi nhap trong `description` cho den khi backend co field rieng.
