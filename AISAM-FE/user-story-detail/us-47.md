# US-47 - Xử lý callback và webhook thanh toán

> Migration notice: callback/webhook muc tieu phai cap nhat Workspace Subscription hoac Credit Wallet theo `PaymentType`, tu choi giao dich lam vuot Maximum Credit Balance va dam bao idempotency.

## 1. User Story

**Là** hệ thống,
**tôi muốn** nhận và xử lý callback và webhook từ PayOS,
**để** đồng bộ trạng thái thanh toán, kích hoạt subscription, và cập nhật lịch sử giao dịch một cách tự động.

---

## 2. Mục tiêu

Hoàn thiện 2 endpoint `POST /api/payment/callback` và `POST /api/payment/webhook` (hiện đang là stub) để tích hợp thực tế với PayOS: validate checksum, tra cứu payment record, cập nhật trạng thái Payment, kích hoạt/tạo Subscription, và redirect user về FE với kết quả tương ứng. Phía FE nhận redirect từ callback và hiển thị kết quả cho người dùng (toast thành công/thất bại) đồng thời tự động refetch subscription và payment history. US-47 bổ sung và hoàn thiện flow thanh toán đã được khởi tạo ở US-44.

---

## 3. Phạm vi

### Trong phạm vi

#### Backend (phần chính)

- **Callback endpoint** (`POST /api/payment/callback`):
  - Nhận query params từ PayOS redirect (bao gồm `id`, `code`, `status`, `orderCode`).
  - Validate checksum với `PayOSSettings.ChecksumKey`.
  - Tra cứu Payment record theo `orderCode` (hoặc `transactionId`).
  - Cập nhật `Payment.Status`:
    - `PAID` → `Success`.
    - `CANCELLED` → `Failed`.
  - Nếu thanh toán thành công: kích hoạt/tạo Subscription:
    - Tìm hoặc tạo `Subscription` record cho profile.
    - Set `IsActive = true`, `StartDate = now`, `EndDate = now + 1 month` (hoặc theo plan).
    - Lưu `PayOSOrderCode`, `PayOSPaymentLinkId` vào Subscription.
  - Redirect user đến `ReturnUrl` (FE) với query params: `?checkout=success` hoặc `?checkout=failed&reason=...`.
  - `[AllowAnonymous]` — không cần JWT, không cần X-Profile-Id.

- **Webhook endpoint** (`POST /api/payment/webhook`):
  - Nhận JSON payload từ PayOS (bao gồm `orderCode`, `amount`, `description`, `accountNumber`, `reference`, `transactionDateTime`, `paymentLinkId`, `code`, `status`).
  - Validate checksum từ header `x-payos-signature` (hoặc trong body).
  - Tra cứu Payment record theo `orderCode` / `paymentLinkId`.
  - Cập nhật `Payment.Status`, `Payment.TransactionId`, `Payment.PaymentMethod`.
  - Nếu thanh toán thành công và subscription chưa active: kích hoạt subscription.
  - Trả về HTTP 200 cho PayOS (xác nhận đã nhận).
  - `[AllowAnonymous]` — PayOS gọi server-to-server.

- **Middleware exception**: `/api/payment/callback` và `/api/payment/webhook` đã được exclude khỏi X-Profile-Id check (ActiveProfileMiddleware).

- **Payment record creation**: Khi `POST /api/payment/checkout` được gọi (US-44), BE phải tạo Payment record với status `Pending` để callback/webhook có thể tra cứu.

- **Subscription activation logic**:
  - Nếu profile đã có subscription active: gia hạn (cập nhật EndDate).
  - Nếu chưa có: tạo mới Subscription với plan tương ứng.
  - Plan mapping: `PlanCode` từ checkout request → `SubscriptionPlanEnum`.

#### Frontend (bổ sung cho US-44)

- **Redirect handling nâng cao**: thay vì chỉ parse `?checkout=success|cancelled`, FE parse thêm các query params thực tế từ callback redirect:
  - `?checkout=success` → toast + refetch.
  - `?checkout=failed&reason=...` → toast lỗi với reason.
  - `?checkout=pending` → toast "Giao dịch đang xử lý..." + polling subscription.
- **Polling subscription sau callback**: nếu webhook chưa kịp cập nhật subscription khi user redirect về FE:
  - Poll `GET /api/payment/subscription/current` mỗi 3 giây, tối đa 10 lần.
  - Khi subscription active → toast "Subscription đã được kích hoạt!" + refetch.
  - Hết 10 lần → toast "Vui lòng chờ trong giây lát..." + nút "Kiểm tra lại".
- **Toast messages**:
  - `checkout=success` + subscription active → "✅ Thanh toán thành công! Gói đã được kích hoạt."
  - `checkout=success` + subscription chưa active → "✅ Thanh toán thành công! Đang kích hoạt gói..." + polling.
  - `checkout=failed&reason=...` → "❌ Thanh toán thất bại: {reason}".
  - `checkout=cancelled` → "ℹ️ Bạn đã hủy thanh toán."

### Ngoài phạm vi

- Retry webhook khi PayOS gọi thất bại: deferred (PayOS tự retry).
- Refund workflow qua webhook: deferred.
- Email confirmation sau thanh toán: deferred.
- Invoice generation: deferred.
- Webhook dashboard/logs trong admin UI: deferred.
- Xử lý nhiều webhook cho cùng một giao dịch (idempotency): có thể implement nhưng MVP chấp nhận risk.

- **Phụ:** User Web App (frontend — nhận redirect, hiển thị kết quả), `PaymentService`, `PaymentRepository`, `SubscriptionRepository`, React Query cache.

## 5. Tiền điều kiện

- PayOS settings đã được cấu hình hợp lệ (ClientId, ApiKey, ChecksumKey, ReturnUrl, CancelUrl).
- `POST /api/payment/checkout` đã tạo Payment record với trạng thái `Pending`.
- Callback và webhook URL đã được đăng ký với PayOS (qua PayOS dashboard hoặc qua API create payment link).
- `ActiveProfileMiddleware` đã bypass cho `/api/payment/callback` và `/api/payment/webhook`.

2. FE parse query params:

   - `checkout=cancelled`:
     - Toast "ℹ️ Bạn đã hủy thanh toán."
3. Gọi refetch: subscription + quota + payment history.
4. Sau 3 giây, xóa query params khỏi URL (replaceState).

## 7. Luồng ngoại lệ

| Mã | Trường hợp | Kết quả mong đợi |
| --- | --- | --- |
| EX-01 | PayOS callback thiếu checksum hoặc checksum invalid | BE trả lỗi, không redirect FE; PayOS có thể retry. |
| EX-02 | Callback không tìm thấy Payment record theo orderCode | BE trả 404, log warning. |

| EX-07 | Polling subscription hết 10 lần vẫn chưa active | Toast warning + "Kiểm tra lại" button. User click → refetch subscription. |
| EX-08 | PayOS config thiếu → callback/webhook trả 503 | Như hiện tại (stub), log rõ config thiếu. |

## 9. API Contracts

### 9.1 PayOS Callback (PayOS → BE)

```
POST /api/payment/callback?code=xxx&id=yyy&orderCode=123&status=PAID
```

`[AllowAnonymous]`

#### BE xử lý

1. Validate checksum từ query params (nếu PayOS gửi).
2. Tìm Payment bằng `orderCode`.
3. Cập nhật Payment:
   - `status` = Success/Failed.
   - `transactionId` = `id` từ PayOS.
   - `paymentMethod` = "PayOS".
4. Nếu Success: kích hoạt subscription.
5. Redirect đến `_settings.ReturnUrl` với query params:
   - Success → `?checkout=success`
   - Failed → `?checkout=failed&reason=...`

### 9.2 PayOS Webhook (PayOS → BE)

```
POST /api/payment/webhook
Content-Type: application/json
x-payos-signature: <checksum>
```

`[AllowAnonymous]`

#### Request Body
```json
{
  "orderCode": 123456789,
  "amount": 299000,
  "description": "Thanh toan goi Plus",
  "accountNumber": "1234567890",
  "reference": "REF123",
  "transactionDateTime": "2026-06-03T15:00:00Z",
  "paymentLinkId": "abc123",
  "code": "00",
  "status": "PAID"
}
```

#### BE xử lý

1. Validate signature từ header `x-payos-signature` (hoặc từ body tùy PayOS config).
2. Tìm Payment bằng `orderCode` hoặc `paymentLinkId`.
3. Cập nhật Payment:
   - `status` = Success (nếu `code = "00"`).
   - `transactionId` = `reference`.
   - `paymentMethod` = "PayOS".
4. Nếu Success: kích hoạt subscription (nếu chưa active).
5. Trả về HTTP 200.

#### Response (200 OK)
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Webhook processed successfully.",
  "timestamp": "2026-06-03T15:00:00Z"
}
```

### 9.3 FE kiểm tra subscription (polling)

```
GET /api/payment/subscription/current
```

Đã defined ở US-44. FE gọi polling khi nhận `checkout=success` nhưng subscription chưa active.

## 12. Acceptance Criteria

### AC-01 - Callback xử lý thanh toán thành công

**Given** PayOS redirect callback với params hợp lệ
**When** BE nhận request
**Then** validate checksum, cập nhật Payment → Success, kích hoạt Subscription
**And** redirect user đến FE với `?checkout=success`.

### AC-02 - Callback xử lý thanh toán thất bại

**Given** PayOS redirect callback với status thất bại
**Then** cập nhật Payment → Failed
**And** redirect user đến FE với `?checkout=failed&reason=...`.

### AC-03 - Webhook xử lý thanh toán

**Given** PayOS gửi webhook với JSON payload hợp lệ
**When** BE nhận request
**Then** validate signature, cập nhật Payment, kích hoạt Subscription
**And** trả về HTTP 200.

### AC-04 - FE nhận redirect success

**Given** FE nhận redirect `?checkout=success`
**When** subscription active
**Then** toast "Thanh toán thành công!" + refetch.

### AC-05 - FE polling khi subscription chưa active

**Given** FE nhận `?checkout=success` nhưng subscription chưa active
**When** polling mỗi 3s
**Then** khi subscription active → toast + refetch.
**And** timeout sau 10 lần → toast warning + "Kiểm tra lại".

### AC-06 - FE xử lý checkout cancelled

**Given** FE nhận `?checkout=cancelled`
**Then** toast "Bạn đã hủy thanh toán."

### AC-07 - Webhook đến trước callback

**Given** webhook active subscription trước
**When** callback đến sau
**Then** callback phát hiện subscription đã active → bỏ qua, redirect FE success.

### AC-08 - Idempotency cho webhook

**Given** PayOS gửi webhook nhiều lần cho cùng giao dịch
**When** Payment status đã là Success
**Then** BE bỏ qua (no-op), trả về 200.

#### HandleCallbackAsync implementation

```csharp
public async Task<GenericResponse<bool>> HandleCallbackAsync(IQueryCollection query, CancellationToken cancellationToken)
{
    if (!HasPayOsConfig())
        return GenericResponse<bool>.CreateError("PayOS is not configured.", HttpStatusCode.ServiceUnavailable, "PAYOS_NOT_CONFIGURED");

    // 1. Validate checksum from query params
    // 2. Extract orderCode, status, id
    var orderCode = query["orderCode"].FirstOrDefault();
    var status = query["status"].FirstOrDefault();
    var transactionId = query["id"].FirstOrDefault();

    // 3. Find pending payment by orderCode
    var payment = await _paymentRepository.GetByReferenceAsync(orderCode, cancellationToken);
    if (payment == null)
        return GenericResponse<bool>.CreateError("Payment not found.", HttpStatusCode.NotFound);

    // 4. Update payment status
    payment.Status = status == "PAID" ? PaymentStatusEnum.Success : PaymentStatusEnum.Failed;
    payment.TransactionId = transactionId;
    payment.PaymentMethod = "PayOS";
    await _paymentRepository.UpdateAsync(payment, cancellationToken);

    // 5. Activate subscription if success
    if (payment.Status == PaymentStatusEnum.Success && payment.SubscriptionId.HasValue)
    {
        var subscription = await _subscriptionRepository.GetByIdAsync(payment.SubscriptionId.Value, cancellationToken);
        if (subscription != null && !subscription.IsActive)
        {
            subscription.IsActive = true;
            subscription.StartDate = DateTime.UtcNow;
            subscription.EndDate = DateTime.UtcNow.AddMonths(1);
            await _subscriptionRepository.UpdateAsync(subscription, cancellationToken);
        }
    }

    // 6. Redirect handled by controller
    return GenericResponse<bool>.CreateSuccess(true);
}

// HTTP Redirect in controller
// HttpContext.Response.Redirect($"{_settings.ReturnUrl}?checkout=success");
```

#### Subscription activation logic (shared)

```csharp
private async Task ActivateSubscriptionAsync(Guid subscriptionId, string orderCode, string paymentLinkId, CancellationToken cancellationToken)
{
    var subscription = await _subscriptionRepository.GetByIdAsync(subscriptionId, cancellationToken);
    if (subscription == null) return;

    if (subscription.IsActive)
    {
        // Renew: extend end date
        subscription.EndDate = DateTime.UtcNow.AddMonths(1);
    }
    else
    {
        // Activate
        subscription.IsActive = true;
        subscription.StartDate = DateTime.UtcNow;
        subscription.EndDate ??= DateTime.UtcNow.AddMonths(1);
    }

    subscription.PayOSOrderCode = orderCode;
    subscription.PayOSPaymentLinkId = paymentLinkId;
    subscription.UpdatedAt = DateTime.UtcNow;
    await _subscriptionRepository.UpdateAsync(subscription, cancellationToken);
}
```

### Frontend - Next.js / React + TypeScript

#### Bổ sung vào US-44 PaymentPage

```typescript
// features/payment/components/payment-page.tsx
// Bổ sung vào useEffect xử lý redirect params

useEffect(() => {
  const checkout = searchParams.get("checkout");
  const reason = searchParams.get("reason");

  if (checkout === "success") {
    handleCheckoutSuccess();
  } else if (checkout === "failed") {
    toast.error(`❌ Thanh toán thất bại: ${reason ?? "Lỗi không xác định"}`);
    router.replace("/payment");
  } else if (checkout === "cancelled") {
    toast.info("ℹ️ Bạn đã hủy thanh toán.");
    router.replace("/payment");
  }
}, [checkoutStatus]);

async function handleCheckoutSuccess() {
  toast.success("✅ Thanh toán thành công!");

  // Refetch subscription, quota, history
  subscription.refetch();
  quota.refetch();
  history.refetch();

  // Poll subscription if not active yet
  const maxAttempts = 10;
  for (let i = 0; i < maxAttempts; i++) {
    await new Promise((r) => setTimeout(r, 3000));
    const result = await subscription.refetch();
    if (result.data?.data?.status === "Active") {
      toast.success(`✅ Gói ${result.data.data.planName} đã được kích hoạt!`);
      break;
    }
    if (i === maxAttempts - 1) {
      toast.warning("⚠️ Gói chưa được kích hoạt. Vui lòng kiểm tra lại.", {
        action: {
          label: "Kiểm tra lại",
          onClick: () => subscription.refetch(),
        },
      });
    }
  }

  router.replace("/payment");
}
```
