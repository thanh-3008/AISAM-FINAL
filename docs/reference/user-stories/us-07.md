# US-07 Frontend Detail - Xac minh email

## 1. User story

La nguoi dung moi, toi muon xac minh email de xac nhan tai khoan cua minh.

## 2. Muc tieu frontend

- Cung cap trang nhan `token` tu link email verification.
- Goi dung endpoint verify email cua backend.
- Hien trang thai thanh cong/that bai ro rang.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `docs/main/requirements.md` muc `6.1` yeu cau he thong ho tro xac minh email.

### Backend plan lien quan

- `docs/archive/plans/backend-code-plan.md` Phase 3 va `CODEBASE_UPDATE.md` Phase A xac nhan email verification da active.

### Backend implementation thuc te

- Endpoint: `GET /api/Auth/verify-email?token=...`
- Authorization: khong can
- Success response: `200 OK`
- Error response: `400 Bad Request` neu token khong hop le/het han

### Hanh vi backend can frontend phai follow

- Token duoc truyen qua query string
- Backend khong tu dong login user sau verify
- Success message: `Email verified successfully. You can now login.`

## 4. Pham vi frontend

### Trong pham vi

- Trang `/verify-email`
- Doc `token` tu query param
- Goi API verify
- Hien success/error state
- Cung cap CTA ve `/login`

### Ngoai pham vi

- Gui lai email verification: thuoc `US-08`

## 5. API contract can dung

### Request

`GET /api/Auth/verify-email?token=<token>`

### Success response

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "Email verified successfully. You can now login.",
  "statusCode": 200,
  "data": null,
  "error": null
}
```

### Error response

HTTP: `400 Bad Request`

```json
{
  "success": false,
  "message": "Invalid or expired verification token",
  "statusCode": 400,
  "data": null,
  "error": {
    "errorMessage": "Invalid or expired verification token"
  }
}
```

## 6. UI/UX spec

### Route

- Route: `/verify-email?token=...`

### States

1. Pending:
   - `Verifying your email...`
2. Success:
   - message thanh cong
   - CTA `Go to login`
3. Error:
   - message token invalid/expired
   - CTA `Resend verification email`

## 7. Validation frontend

- Neu thieu `token` trong query:
  - khong goi API
  - hien ngay error state `Missing verification token`

## 8. Data flow frontend

1. User mo link email verification
2. Frontend doc `token` tu URL
3. Neu co token:
   - goi `GET /api/Auth/verify-email`
4. Neu thanh cong:
   - hien success state
   - cho phep di den `/login`
5. Neu that bai:
   - hien error state
   - goi y `resend verification`

## 9. State can xu ly

### Loading state

- Full page card/trang thai dang xu ly

### Success state

- Hien thong bao verify thanh cong

### Error state

- Token thieu
- Token invalid/expired
- Loi he thong `500`

## 10. Auth/session impact

- Verify email khong tao session moi
- Frontend khong duoc tu dong luu auth state chi vi verify thanh cong

## 11. Dieu huong sau verify

- CTA chinh: `/login`
- Khong auto redirect manh tay neu user can doc message

## 12. Acceptance criteria

### AC-01

Trang verify doc token tu query string va goi dung endpoint backend.

### AC-02

Khi verify thanh cong, frontend hien message thanh cong va CTA ve login.

### AC-03

Khi token khong hop le hoac het han, frontend hien error state ro rang.

### AC-04

Khi URL khong co token, frontend khong goi API vo nghia.

## 13. Test cases frontend

### FE-01

Co token hop le se goi API va hien success state.

### FE-02

Token invalid se hien error state.

### FE-03

Thieu token se hien message loi ma khong goi API.

## 14. Ghi chu implementation

- Backend dung `GET`, khong phai `POST` cho verify email.
- Backend khong login user sau verify, nen frontend khong duoc redirect vao protected area.
- Neu user da dang nhap truoc do, verify page van co the duoc mo tu email; khong can pha session hien tai.
