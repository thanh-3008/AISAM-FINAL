# US-26 - Chat với AI theo ngữ cảnh profile

## 1. User Story

**Là** người dùng,
**tôi muốn** chat với AI trong ngữ cảnh profile, brand và product để brainstorming nội dung liên tục,
**để** có thể trao đổi qua lại với AI, nhận gợi ý, tinh chỉnh ý tưởng một cách tự nhiên như đang trò chuyện.

---

## 2. Mục tiêu

Cung cấp giao diện chat chuyên biệt cho phép người dùng trò chuyện với AI theo từng conversation có ngữ cảnh (profile, brand, product, ad type). Mỗi conversation là một chuỗi hội thoại liên tục, lưu trữ toàn bộ lịch sử tin nhắn. Người dùng có thể:
- Tạo nhiều conversation với các ngữ cảnh khác nhau.
- Chuyển đổi giữa các conversation.
- Xem lịch sử tin nhắn trong từng conversation.
- Gửi tin nhắn mới và nhận phản hồi AI theo thời gian thực.
- Quản lý conversation (đổi tên, xoá).
- Copy tin nhắn, render markdown trong phản hồi AI.

---

## 3. Phạm vi

### Trong phạm vi

- Màn hình Chat chuyên dụng (`/ai/chat`) với layout 2 panel: conversation list (trái) + chat window (phải).
- Danh sách conversation: hiển thị tất cả conversation của profile, sắp xếp theo hoạt động gần nhất.
- Tạo conversation mới với context selector (brand, product, ad type).
- Chat window: hiển thị toàn bộ tin nhắn (user + AI) theo thời gian thực.
- Gửi tin nhắn: gọi `POST /api/ai/chat` với `ChatRequest`.
- Tự động tìm hoặc tạo conversation khi gửi tin nhắn đầu tiên với context mới.
- Load lịch sử conversation: gọi `GET /api/conversations/{id}` để lấy messages.
- Xoá conversation: gọi `DELETE /api/conversations/{id}`.
- Markdown rendering cho tin nhắn AI.
- Copy tin nhắn (user hoặc AI) vào clipboard.
- Typing indicator khi chờ AI response.
- Auto-scroll xuống tin nhắn mới nhất.
- Timestamps trên mỗi tin nhắn.
- Toast thông báo thành công / lỗi.
- Empty state cho conversation mới và danh sách rỗng.

### Ngoài phạm vi

- Chat với file đính kèm (image, document).
- Chat voice/video.
- Streaming response (SSE/WebSocket) — hiện tại API trả response đồng bộ.
- Real-time multi-user chat.
- Chat template / prompt library.
- Generate content trực tiếp từ chat (có thể chuyển đến US-22).
- US-27 - Xem lịch sử hội thoại AI (danh sách conversation riêng, đã có trong story khác).

---

## 4. Actor

- **Chính:** Người dùng đã đăng nhập, có profile đang active.
- **Phụ:** User Web App (frontend), Backend API (GeminiController/AIService, ConversationController/ConversationService), Gemini AI provider, PostgreSQL.

---

## 5. Tiền điều kiện

- Người dùng đã đăng nhập và có JWT access token hợp lệ.
- Người dùng đã chọn active profile (`X-Profile-Id` header hợp lệ).
- (Tuỳ chọn) Có ít nhất một brand thuộc profile nếu muốn chat với brand context.
- `GeminiSettings` (API key) đã được cấu hình trên backend.

## 6. Luồng nghiệp vụ chính

### 6.1 Mở màn hình Chat

1. Người dùng truy cập màn hình Chat (`/ai/chat`).
2. Hệ thống hiển thị layout 2 panel:
   - **Panel trái**: danh sách conversation (sidebar).
   - **Panel phải**: chat window (hiện tại).
3. Hệ thống gọi `GET /api/conversations?page=1&pageSize=50` để load danh sách conversation của profile.
4. Nếu có conversation gần nhất:
   - Tự động chọn conversation đó.
   - Gọi `GET /api/conversations/{id}` để load messages.
   - Hiển thị messages trong chat window.
5. Nếu chưa có conversation nào:
   - Hiển thị empty state: "Bắt đầu cuộc trò chuyện mới với AI".
   - Hiển thị context selector để người dùng chọn brand, product, ad type.

### 6.2 Tạo conversation mới

1. Trong sidebar, người dùng nhấn nút **"+ New Chat"**.
2. Hệ thống hiển thị context selector (có thể là modal hoặc inline form):
   - **Brand** (dropdown, tuỳ chọn) — danh sách brand thuộc profile active.
   - **Product** (dropdown, tuỳ chọn) — populate theo brand đã chọn.
   - **Ad Type** (dropdown, mặc định `TextOnly`).
   - **Title** (text input, tuỳ chọn) — tên cho conversation; nếu để trống, backend tự đặt từ message đầu tiên.
3. Người dùng chọn context và nhấn **"Start Chat"**.
4. Hệ thống chuyển đến chat window mới (chưa có message nào).
5. Người dùng nhập tin nhắn đầu tiên và gửi.
6. Frontend gọi `POST /api/ai/chat` với `ChatRequest` (không có `conversationId`).
7. Backend tự động tìm conversation active theo context hoặc tạo mới.
8. Backend lưu user message, gọi Gemini, lưu AI response, trả về `ChatResponse`.
9. Frontend:
   - Hiển thị user message + AI response trong chat window.
   - Cập nhật sidebar với conversation mới (nếu vừa tạo).
   - Lưu `conversationId` để các tin nhắn sau đó dùng tiếp.

### 6.3 Gửi tin nhắn trong conversation hiện tại

1. Người dùng đang ở một conversation có sẵn.
2. Người dùng nhập tin nhắn vào textarea và nhấn **Send** (hoặc Enter).
3. Frontend:
   - Hiển thị user message ngay lập tức (optimistic) với trạng thái "sending".
   - Gọi `POST /api/ai/chat` với `ChatRequest` (bao gồm `conversationId`).
   - Hiển thị typing indicator.
4. Backend validate conversation ownership, lưu user message, gọi Gemini, lưu AI response.
5. Frontend nhận response:
   - Ẩn typing indicator.
   - Hiển thị AI response.
   - Cập nhật trạng thái user message thành "sent".
   - Scroll xuống message mới nhất.
6. Nếu lỗi:
   - Ẩn typing indicator.
   - Hiển thị AI error message (backend đã lưu error message như một tin nhắn AI).
   - Đánh dấu user message với trạng thái "error".

### 6.4 Chuyển đổi conversation

1. Người dùng click vào một conversation khác trong sidebar.
2. Frontend:
   - Gọi `GET /api/conversations/{id}` để load messages.
   - Hiển thị messages trong chat window.
   - Đánh dấu conversation này là active trong sidebar.
3. Người dùng có thể tiếp tục chat trong conversation này.

### 6.5 Xoá conversation

1. Người dùng hover vào conversation trong sidebar, thấy nút **delete** (icon thùng rác).
2. Người dùng click delete.
3. Frontend hiển thị dialog xác nhận: "Xoá cuộc trò chuyện này? Hành động này không thể hoàn tác."
4. Người dùng xác nhận.
5. Frontend gọi `DELETE /api/conversations/{id}`.
6. Backend soft-delete conversation (`IsDeleted = true`, `IsActive = false`).
7. Frontend:
   - Xoá conversation khỏi sidebar.
   - Nếu conversation đang active, chuyển sang conversation khác hoặc empty state.
   - Toast "Đã xoá cuộc trò chuyện."

### 6.6 Chat với context khác (chuyển context)

1. Từ một conversation đang active, người dùng có thể muốn chat về một brand khác.
2. Người dùng nhấn **"+ New Chat"** để tạo conversation mới với context khác.
3. Conversation cũ vẫn được lưu trong sidebar để quay lại sau.

## 7. Luồng ngoại lệ

| Mã | Trường hợp | Kết quả mong đợi |
| --- | --- | --- |
| EX-01 | Conversation không tồn tại hoặc không thuộc profile | Backend trả `404 Not Found` khi load messages hoặc gửi tin nhắn; frontend hiển thị lỗi và chuyển về empty state. |
| EX-02 | Gemini API key chưa cấu hình | Backend trả `503 Service Unavailable`; frontend hiển thị thông báo "Dịch vụ AI chưa được cấu hình." và disable nút Send. |
| EX-03 | Gemini API trả lỗi (network, timeout) | Backend bắt exception, lưu AI message với nội dung lỗi; frontend hiển thị AI response là error message. |
| EX-04 | Brand không tồn tại hoặc không thuộc profile | Backend trả `404 Not Found` khi validate brand; frontend hiển thị lỗi và yêu cầu chọn brand khác. |
| EX-05 | Product không thuộc brand đã chọn | Backend trả `400 Bad Request`; frontend hiển thị lỗi validation. |
| EX-06 | JWT hết hạn hoặc không hợp lệ | Backend trả `401 Unauthorized`; frontend tự động refresh token hoặc chuyển hướng đăng nhập. |
| EX-07 | X-Profile-Id thiếu hoặc không thuộc user | Backend trả `400 Bad Request` / `403 Forbidden`; frontend hiển thị lỗi. |
| EX-08 | Người dùng nhấn Send nhiều lần | Frontend disable nút Send sau lần nhấn đầu tiên đến khi có phản hồi. |
| EX-09 | Tin nhắn rỗng hoặc chỉ khoảng trắng | Frontend validate tin nhắn không được rỗng trước khi gửi; disable nút Send khi input trống. |
| EX-10 | Xoá conversation đang active | Frontend xác nhận trước khi xoá; sau khi xoá, chuyển sang conversation khác hoặc empty state. |
| EX-11 | Load danh sách conversation thất bại | Toast "Không thể tải danh sách cuộc trò chuyện." + nút Retry. |
| EX-12 | Load messages conversation thất bại | Toast "Không thể tải tin nhắn." + nút Retry. |

## 8. Quy tắc nghiệp vụ

| Mã | Quy tắc |
| --- | --- |
| BR-01 | `ProfileId` được lấy từ `X-Profile-Id` header đã được middleware validate, không lấy từ request body. |
| BR-02 | Chat KHÔNG tiêu thụ prompt quota (không gọi `QuotaService.EnsurePromptQuotaAsync`). |
| BR-03 | Nếu `conversationId` không được gửi, backend tự động tìm conversation active theo `(profileId, brandId, productId, adType)` hoặc tạo mới nếu chưa có. |
| BR-04 | Nếu `conversationId` được gửi, backend validate conversation thuộc profile và tiếp tục conversation đó. |
| BR-05 | Mỗi tin nhắn user và AI đều được lưu vào DB (`ChatMessage`). |
| BR-06 | Khi Gemini fail, backend vẫn lưu AI message với nội dung lỗi ("AI chat is temporarily unavailable."). |
| BR-07 | Conversation có `Title` được đặt từ message đầu tiên (backend tự set, truncate 255 ký tự). |
| BR-08 | Conversation chỉ có một `IsActive = true` cho mỗi context `(profileId, brandId, productId, adType)`. Khi tạo mới, backend auto-find active hoặc tạo mới. |
| BR-09 | `BrandId` là tuỳ chọn trong chat. Nếu `ProductId` có giá trị thì `BrandId` bắt buộc. |
| BR-10 | Tin nhắn được sắp xếp theo `CreatedAt` tăng dần (cũ nhất trước, mới nhất sau). |
| BR-11 | Danh sách conversation được sắp xếp theo `UpdatedAt` giảm dần (hoạt động gần nhất trước). |
| BR-12 | Soft-delete conversation: set `IsDeleted = true` và `IsActive = false`. Tin nhắn vẫn giữ trong DB. |
| BR-13 | Chat context (brand, product, ad type) KHÔNG thể thay đổi sau khi conversation đã tạo. Nếu muốn đổi context, tạo conversation mới. |

## 9. API Contracts

### 9.1 Send Chat Message

```
POST /api/ai/chat
```

#### Headers bắt buộc

```http
Authorization: Bearer <access-token>
X-Profile-Id: <owned-profile-guid>
```

#### Request Body

```json
{
  "brandId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "productId": null,
  "adType": 0,
  "message": "Can you suggest a catchy headline for our summer sale?",
  "conversationId": null
}
```

#### Tham số

| Field | Kiểu | Bắt buộc | Mô tả |
| --- | --- | --- | --- |
| `brandId` | `Guid?` | Không | Brand context cho chat. Nếu có, validate ownership. |
| `productId` | `Guid?` | Không | Product context. Nếu có, `brandId` bắt buộc. |
| `adType` | `int` | Có | Ad type context: 0=TextOnly, 1=ImageText, 2=VideoText. |
| `message` | `string` | Có | Nội dung tin nhắn. |
| `conversationId` | `Guid?` | Không | ID conversation để tiếp tục. Nếu null, backend auto-find/tạo mới. |

#### Response thành công (`200 OK`)

```json
{
  "success": true,
  "statusCode": 200,
  "message": null,
  "data": {
    "conversationId": "conv-uuid",
    "response": "Sure! How about: 🔥 **Summer Sale Alert!** 🔥\n\n*Up to 50% off on all items — but hurry, stocks are limited!*\n\nOr try this shorter version:\n☀️ *Beat the heat with our biggest sale of the year!* ☀️"
  }
}
```

### 9.4 Delete Conversation

```
DELETE /api/conversations/{id}
```

#### Response thành công (`200 OK`)

```json
{
  "success": true,
  "statusCode": 200,
  "message": "Conversation deleted successfully.",
  "data": true
}
```

### 9.5 Response Error Codes

| HTTP Status | errorCode | Trường hợp |
| --- | --- | --- |
| `401 Unauthorized` | — | JWT thiếu hoặc không hợp lệ. |
| `400 Bad Request` | — | `X-Profile-Id` thiếu, sai format, product có brand không có, hoặc message rỗng. |
| `403 Forbidden` | — | Profile không thuộc user đang đăng nhập. |
| `404 Not Found` | — | Conversation/Brand/Product không tồn tại hoặc không thuộc profile. |
| `503 Service Unavailable` | — | Gemini API key chưa cấu hình hoặc AI service tạm thời không khả dụng. |
| `500 Internal Server Error` | — | Lỗi hệ thống không mong đợi. |

| --- | --- | --- |
| `0` | `TextOnly` | Chỉ văn bản |
| `1` | `ImageText` | Văn bản + hình ảnh |
| `2` | `VideoText` | Văn bản + video |

**`senderType`:**

| Giá trị | Tên | Mô tả |
| --- | --- | --- |
| `0` | `User` | Người dùng |
| `1` | `AI` | AI (Gemini) |

### 10.2 Conversation Sidebar

**Header:**
- Tiêu đề "Conversations".
- Nút **"+ New Chat"** (primary).

**Search (tuỳ chọn):**
- Search box tìm conversation theo title.
- Gọi `GET /api/conversations?searchTerm=...` hoặc client-side filter.

**Danh sách:**
- Mỗi item hiển thị:
  - **Icon** (avatar mặc định hoặc icon chat).
  - **Title** (1 dòng, truncate).
  - **Brand/Product name** (phụ đề, nhỏ, grey).
  - **Last message** (1 dòng truncate).
  - **Timestamp** (relative time: "2 phút trước").
  - **Message count** (optional).
  - **Active indicator** (nếu đang được chọn).
  - **Delete button** (icon, hiển thị khi hover).
- Sắp xếp: mới nhất trước (theo `updatedAt`).
- Scroll nếu nhiều item.
- Empty state: "Chưa có cuộc trò chuyện nào."

### 10.3 Chat Window

**Context Info Bar (trên cùng):**
- Hiển thị brand name, product name (nếu có), ad type của conversation hiện tại.
- Có thể là một badge nhỏ.

**Message List:**

### AC-01 - Xem danh sách conversations

**When** modal mở ra
**Then** hiển thị context selector (brand, product, ad type)
**When** người dùng chọn context và nhấn "Start Chat"
**Then** chuyển đến chat window mới
**And** tin nhắn đầu tiên tạo conversation mới.

**Given** conversation đang active
**When** người dùng nhập tin nhắn và nhấn Send
**Then** user message hiển thị ngay trong chat

**When** response đến

```typescript
// hooks/use-chat.ts
function useChat() {
  const [isSending, setIsSending] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const sendMessage = async (
    payload: ChatRequest
  ): Promise<ChatResponse | null> => {
    setIsSending(true);
    setError(null);
    try {
      const result = await aiApi.chat(payload);
      if (result.success) {
        return result.data;
      } else {
        setError(result.message ?? "Failed to send message.");
        return null;
      }
    } catch (err) {
      setError("Network error. Please try again.");
      return null;
    } finally {
      setIsSending(false);
    }
  };

  return { sendMessage, isSending, error };
}
```

```typescript
// hooks/use-conversations.ts
function useConversations() {
  const [conversations, setConversations] = useState<ConversationSummary[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [activeId, setActiveId] = useState<string | null>(null);

  const fetchConversations = async () => {
    setIsLoading(true);
    try {
      const result = await conversationApi.list({ pageSize: 50 });
      if (result.success && result.data) {
        setConversations(result.data.data);
      }
    } finally {
      setIsLoading(false);
    }
  };

  const deleteConversation = async (id: string) => {
    const result = await conversationApi.delete(id);
    if (result.success) {
      setConversations((prev) => prev.filter((c) => c.id !== id));
      if (activeId === id) {
        setActiveId(null);
      }
      return true;
    }
    return false;
  };

  return {
    conversations,
    isLoading,
    activeId,
    setActiveId,
    fetchConversations,
    deleteConversation,
  };
}
```

```tsx
            { value: 2, label: "VideoText" },
          ]}
        />
        <Input
          label="Title (optional)"
          value={title}

        />
      </ModalBody>

}
```
