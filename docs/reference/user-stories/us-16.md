# US-16 - Gan profile scope cho brand

## 1. User Story

**La** he thong,  
**toi muon** chi cho phep truy cap brand thuoc profile dang hoat dong,  
**de** dam bao ownership dung va tranh lo du lieu giua cac business profile.

## 2. Muc Tieu

Dam bao moi thao tac brand tren frontend luon nam trong ngu canh active business profile. Khi nguoi dung doi profile, danh sach brand, form tao brand, chi tiet brand va cac thao tac cap nhat/xoa/khoi phuc phai tu dong scope theo profile moi va khong hien thi du lieu cua profile khac.

## 3. Pham Vi

### Trong pham vi

- Frontend quan ly state `activeProfileId` sau khi nguoi dung chon business profile.
- Man hinh brand chi load brand theo `activeProfileId`.
- Tao brand gan `profileId` bang active profile hien tai.
- Xem, sua, xoa mem va khoi phuc brand chi thanh cong neu brand thuoc profile ma user so huu.
- Reset/refresh brand cache khi active profile thay doi.
- Hien thi empty state neu active profile chua co brand.
- Hien thi loi ro rang khi user chua chon profile, profile khong ton tai, hoac profile khong thuoc user.
- Khong cho phep frontend dung `profileId` lay tu URL/body tuy y neu khac active profile hien tai.

### Ngoai pham vi

- CRUD brand kit day du: thuoc `US-15`.
- Tao, sua, xoa business profile: thuoc `US-12`, `US-14`.
- Product theo brand: thuoc `US-17`, `US-18`.
- Team/shared profile permission: chua migrate trong MVP, de sau `US-59`.
- Backend refactor Brand API sang bat buoc `X-Profile-Id`: khong bat buoc trong story frontend nay.

## 4. Actor

- **Chinh:** User Web App.
- **Phu:** Nguoi dung da dang nhap, Backend API, PostgreSQL.

## 5. Tien Dieu Kien

- Nguoi dung da dang nhap va co `accessToken` hop le.
- Nguoi dung da co it nhat mot business profile hoac frontend co luong tao profile truoc.
- Frontend co co che luu active profile hien tai.
- Backend hien tai da co `BrandController`, `BrandService`, `BrandRepository` va ownership check theo profile owner.

## 6. Backend Hien Tai Can Bam

Brand API hien tai duoc bao ve bang JWT va scope bang `profileId` trong query/body:

- `GET /api/brands?profileId={activeProfileId}&page=1&pageSize=10&searchTerm=&sortBy=&sortDescending=true&includeDeleted=false`
- `GET /api/brands/{id}`
- `POST /api/brands`
- `PUT /api/brands/{id}`
- `DELETE /api/brands/{id}`
- `POST /api/brands/{id}/restore`

Luu y implementation hien tai:

- `GET /api/brands` bat buoc co `profileId` query.
- `POST /api/brands` bat buoc body co `profileId`.
- `UpdateBrandRequest` co `profileId` nhung backend hien tai khong dung field nay de doi scope; brand duoc update theo profile goc cua brand.
- `GetById`, `Update`, `Delete`, `Restore` lay brand theo `id`, sau do backend kiem tra `brand.ProfileId` co thuoc user trong JWT khong.
- Cac module moi hon nhu Content/AI/Social/Notification dung `X-Profile-Id`, nhung `/api/brands` chua nam trong `ActiveProfileMiddleware`. Frontend van nen luu va gui `X-Profile-Id` chung trong API client de thong nhat, dong thoi tiep tuc gui `profileId` theo contract hien tai cua Brand API.

## 7. Luong Nghiep Vu Chinh

1. Nguoi dung dang nhap vao AISAM.
2. Frontend lay danh sach business profile cua user.
3. Nguoi dung chon mot active profile, hoac frontend auto chon profile dau tien theo quy tac cua app.
4. Frontend luu `activeProfileId` trong app state.
5. Frontend goi `GET /api/brands` voi `profileId = activeProfileId`.
6. Backend kiem tra profile ton tai va `profile.UserId` khop user trong JWT.
7. Backend chi tra ve brand co `Brand.ProfileId = activeProfileId`.
8. Frontend hien thi danh sach brand cua active profile.
9. Khi nguoi dung doi active profile, frontend xoa selection/cache brand cu va load lai danh sach brand theo profile moi.
10. Khi tao brand, frontend gan `profileId = activeProfileId` vao request body.

## 10. API Contract Cho Frontend

### Headers chung

```http
Authorization: Bearer <accessToken>
X-Profile-Id: <activeProfileId>
Content-Type: application/json
```

`X-Profile-Id` nen duoc gui thong nhat trong API client, du Brand API hien tai van scope bang query/body.

### List brand theo active profile


### Response loi can xu ly

| HTTP status | Message/backend behavior | FE xu ly |
| --- | --- | --- |
| `401` | `Invalid token` hoac token thieu/het han | Thu refresh token hoac dua ve login. |
| `400` | `ProfileId is required`, `Profile not found`, `You are not allowed to access this profile` | Hien thi loi va reload/chon lai active profile. |
| `404` | `Brand not found` | Dong detail va quay ve list brand. |
| `500` | `System error` | Hien thi loi he thong, cho phep retry. |

## 11. Yeu Cau Frontend

- Co `activeProfileStore` hoac context dung chung cho toan app.
- API client tu dong gan `Authorization` va `X-Profile-Id` neu da co active profile.
- Brand query key/cache phai bao gom `activeProfileId`, vi du `["brands", activeProfileId, filters]`.
- Khi `activeProfileId` thay doi, invalidate cac query lien quan den brand/product/content cua profile cu.
- Nut tao brand bi disable neu chua co active profile.
- Form tao brand khong cho user tu sua `profileId`; field nay lay tu state.
- Neu detail brand duoc mo bang URL `/brands/{id}`, sau khi fetch phai verify `response.data.profileId === activeProfileId`; neu khong khop thi khong render detail.
- Empty state nen huong nguoi dung tao brand dau tien cho profile dang chon.

## 12. Acceptance Criteria

### AC-01 - Load brand theo active profile

**Given** user da dang nhap va active profile la Profile A  
**When** frontend mo trang Brand  
**Then** frontend goi `GET /api/brands` voi `profileId = Profile A`  
**And** chi hien thi brand co `profileId = Profile A`.

### AC-02 - Doi active profile thi doi danh sach brand

**Given** user dang xem brand cua Profile A  
**When** user chon Profile B lam active profile  
**Then** frontend xoa selected brand/cache cua Profile A  
**And** load lai danh sach brand voi `profileId = Profile B`.

### AC-03 - Tao brand gan dung profile

**Given** active profile la Profile A  
**When** user tao brand moi  
**Then** request body co `profileId = Profile A`  
**And** brand moi xuat hien trong danh sach cua Profile A.

### AC-04 - Khong thao tac khi chua chon profile

**Given** user chua co active profile  
**When** user vao trang Brand  
**Then** frontend khong goi `GET /api/brands`  
**And** hien thi trang thai yeu cau chon hoac tao business profile.

### AC-05 - Chan hien thi brand khac profile

**Given** frontend nhan duoc brand detail co `profileId` khac active profile  
**When** render detail  
**Then** frontend khong hien thi noi dung brand do  
**And** dieu huong ve danh sach brand cua active profile hoac hien thi loi truy cap.

### AC-06 - Xu ly loi ownership tu backend

**Given** request brand dung `profileId` khong thuoc user  
**When** backend tra loi loi ownership  
**Then** frontend hien thi thong bao khong co quyen truy cap profile nay  
**And** xoa active profile khong hop le neu no dang duoc luu local.

### AC-07 - Restore chi nam trong profile hien tai

**Given** view da xoa cua active profile duoc bat `includeDeleted=true`  
**When** user khoi phuc mot brand  
**Then** frontend goi `POST /api/brands/{brandId}/restore`  
**And** reload lai danh sach brand cua active profile hien tai.

## 14. Definition of Done

- Trang Brand tren frontend luon scope theo active profile.
- Moi API call brand co `Authorization` va co du lieu scope profile dung theo contract hien tai.
- Tao brand khong cho user chon/sua `profileId` tuy y.
- Doi active profile khong con hien brand, selected brand, form draft hoac cache cua profile cu.
- Frontend xu ly dung cac loi `401`, `400`, `404`, `500` tu Brand API.
- Co test frontend cho active profile switching va ownership error.
- Khong can migration database cho story nay.

## 15. Phu Thuoc
