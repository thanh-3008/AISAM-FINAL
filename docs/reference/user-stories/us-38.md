# US-38 - Đánh dấu thông báo đã đọc

## 1. User Story

**Là** người dùng,
**tôi muốn** đánh dấu một thông báo hoặc tất cả thông báo là đã đọc để quản lý hộp thư nội bộ,
**để** có thể tập trung vào các thông báo chưa xử lý và giữ unread count phản ánh đúng trạng thái thực tế.

---

## 2. Mục tiêu

Cung cấp các action để người dùng đánh dấu notification là đã đọc: (a) mark read một notification từ bell dropdown, từ detail modal, từ danh sách trang `/notifications`; (b) mark all read từ bell dropdown header và từ trang `/notifications`. Mỗi mutation cập nhật UI ngay lập tức (optimistic update) và toast xác nhận.

---

## 3. Phạm vi

### Trong phạm vi

- **Mark single read** từ bell dropdown: click vào notification item → gọi `POST /api/notifications/{id}/mark-read`.
- **Mark single read** từ detail modal: nút "Đánh dấu đã đọc" trong modal.
- **Mark single read** từ trang `/notifications`: click vào notification item (trước khi mở modal) hoặc nút "Mark read" icon trên item.
- **Mark all read** từ bell dropdown: action "Mark all as read" ở footer dropdown.
- **Mark all read** từ trang `/notifications`: nút "Mark all as read" ở header trang.
- **Optimistic update**: UI chuyển trạng thái ngay lập tức (isRead = true, badge count giảm) trước khi API response.
- **Toast xác nhận** khi thành công: "Đã đánh dấu là đã đọc." / "Đã đánh dấu tất cả là đã đọc."
- **Toast lỗi** khi thất bại: rollback optimistic update, toast lỗi.
- **Auto-mark-on-click**: khi click notification từ bell dropdown, tự động mark read (đã define ở US-36).
- **Invalidate queries**: sau mutation, refresh `notifications` và `unread-count` queries.

### Ngoài phạm vi

- Trang `/notifications` full list: US-37.
- Notification bell + dropdown: US-36.
- Notification detail modal: US-37.
- Xoá notification (BE không hỗ trợ).
- Realtime/SignalR push.

---

## 4. Actor

- **Chính:** Người dùng đã đăng nhập, có active profile, có ít nhất một notification chưa đọc.
- **Phụ:** Backend API (`NotificationsController`), React Query cache.

---

## 5. Tiền điều kiện

- Người dùng đã đăng nhập và có JWT token hợp lệ.
- Người dùng đã chọn active profile (`X-Profile-Id` header).
- Backend `NotificationsController` mark-read và mark-all-read endpoints đã triển khai.
- `X-Profile-Id` tự động gắn bởi fetcher (US-28).

---

## 6. Luồng nghiệp vụ chính

### 6.1 Mark single read từ bell dropdown

1. Người dùng mở notification dropdown (US-36).
2. Click vào một notification chưa đọc.
3. Frontend gọi `POST /api/notifications/{id}/mark-read`.
4. Optimistic update: item chuyển sang trạng thái đã đọc ngay (nền tối hơn, title normal weight, badge giảm).
5. Điều hướng đến trang `/notifications` (theo US-36/US-37).

### 6.2 Mark single read từ detail modal

1. Người dùng mở detail modal trên trang `/notifications` (US-37).
2. Modal hiển thị nút "Đánh dấu đã đọc" (chỉ khi notification chưa đọc).
3. Người dùng click nút.
4. Frontend gọi `POST /api/notifications/{id}/mark-read`.
5. Optimistic update: nút chuyển thành "Đã đọc" (disabled), trạng thái trong modal cập nhật.
6. Toast "Đã đánh dấu là đã đọc."
7. List item cập nhật trạng thái (nếu modal không đóng).

### 6.3 Mark single read từ list item (inline)

1. Trên trang `/notifications`, mỗi notification item có nút/icon "Mark as read" (dấu check tròn).
2. Người dùng click icon "Mark as read" trên item chưa đọc.
3. Frontend gọi `POST /api/notifications/{id}/mark-read`.
4. Optimistic update: item chuyển sang trạng thái đã đọc (title normal weight, ẩn "New" badge, icon check biến mất).
5. Toast "Đã đánh dấu là đã đọc."

### 6.4 Mark all read từ bell dropdown

1. Người dùng mở notification dropdown.
2. Footer dropdown có action "Mark all as read".
3. Click → gọi `POST /api/notifications/mark-all-read`.
4. Optimistic update: tất cả items trong dropdown chuyển trạng thái đã đọc, badge về 0.
5. Toast "Đã đánh dấu tất cả là đã đọc."

### 6.5 Mark all read từ trang /notifications

1. Trên trang `/notifications`, header có nút "Mark all as read" (chỉ hiển thị khi có unread).
2. Click → gọi `POST /api/notifications/mark-all-read`.
3. Optimistic update: tất cả items chuyển sang đã đọc, ẩn "New" badges.
4. Toast "Đã đánh dấu tất cả là đã đọc."
5. Unread count badge trên bell icon (US-36) cập nhật về 0.

## 7. Luồng ngoại lệ

| Mã | Trường hợp | Kết quả mong đợi |
| --- | --- | --- |
| EX-01 | Mark read thất bại (network error) | Rollback optimistic update; toast "Không thể đánh dấu. Vui lòng thử lại." |
| EX-02 | Mark read notification không tồn tại (404) | Backend trả 404; FE toast "Thông báo không tồn tại." + rollback. |
| EX-03 | Mark all read thất bại | Rollback optimistic update (khôi phục badge + trạng thái items); toast lỗi. |
| EX-04 | Double click mark read nhanh | Mutation key dựa trên id nên mutation thứ 2 sẽ chờ mutation thứ 1; không gọi 2 lần. |
| EX-05 | Mark read khi không có unread | Nút "Mark all as read" ẩn, không thể click. |

---

## 8. Quy tắc nghiệp vụ

| Mã | Quy tắc |
| --- | --- |
| BR-01 | Chỉ có thể mark read notification thuộc profile đang active. |
| BR-02 | Mark read là idempotent: gọi nhiều lần trên cùng notification không gây lỗi. |
| BR-03 | Mark all read chỉ mark các notification `isRead = false` AND `isDeleted = false`. |
| BR-04 | Optimistic update rollback nếu API thất bại (dùng `onError` của React Query mutation). |
| BR-05 | Sau mark read, các query keys `["notifications"]` và `["notifications", "unread-count"]` cần invalidate. |

## 9. API Contracts

### 9.1 Mark Single Read

```
POST /api/notifications/{notificationId}/mark-read
```

#### Headers
```http
Authorization: Bearer <access-token>
X-Profile-Id: <owned-profile-guid>
Content-Type: application/json
```

#### Response (200 OK)
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Notification marked as read.",
  "data": true,
  "timestamp": "2026-06-03T15:00:00Z"
}
```

#### Response (404 Not Found)
```json
{
  "success": false,
  "statusCode": 404,
  "message": "Notification not found.",
  "data": null,
  "timestamp": "2026-06-03T15:00:00Z"
}
```

## 12. Acceptance Criteria

### AC-01 - Mark single read từ bell dropdown

**Given** dropdown đang mở
**When** click notification chưa đọc
**Then** gọi `POST /api/notifications/{id}/mark-read`
**And** navigate đến `/notifications`.

### AC-02 - Mark single read từ detail modal

**Given** detail modal đang mở cho notification chưa đọc
**When** click "Đánh dấu đã đọc"
**Then** gọi `POST /api/notifications/{id}/mark-read`
**And** nút chuyển thành "Đã đọc" (disabled)
**And** status trong modal chuyển thành "Đã đọc".

### AC-03 - Mark single read từ list item

**Given** trang `/notifications` đang hiển thị
**When** click icon "Mark as read" trên item chưa đọc
**Then** gọi `POST /api/notifications/{id}/mark-read`
**And** item chuyển trạng thái đã đọc ngay.

### AC-04 - Mark all read từ dropdown

**Given** dropdown đang mở và có unread
**When** click "Mark all as read"
**Then** gọi `POST /api/notifications/mark-all-read`
**And** tất cả items trong dropdown chuyển trạng thái đã đọc.

### AC-05 - Mark all read từ trang /notifications

**Given** trang `/notifications` có unread notifications
**When** click "Mark all as read" ở header
**Then** gọi `POST /api/notifications/mark-all-read`
**And** tất cả notifications chuyển trạng thái đã đọc
**And** badge về 0.

### AC-06 - Optimistic update rollback

**Given** vừa click mark-read
**When** API thất bại
**Then** UI rollback về trạng thái trước đó
**And** toast lỗi.

### AC-07 - Ẩn "Mark all" khi không có unread

**Given** tất cả notifications đã đọc
**Then** ẩn nút "Mark all as read" khỏi header và dropdown.

### AC-08 - Toast confirmations

**Given** mark-read hoặc mark-all-read thành công
**Then** toast "Đã đánh dấu là đã đọc." hoặc "Đã đánh dấu tất cả là đã đọc."

```typescript
// features/notifications/hooks/use-notification-actions.ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { notificationApi } from "@/features/notifications/api/notification-api";
import { useToastStore } from "@/stores/toast-store";

const NOTIFICATION_QUERY_KEYS = {
  all: ["notifications"] as const,
  recent: ["notifications", "recent"] as const,
  list: ["notifications", "list"] as const,
  unreadCount: ["notifications", "unread-count"] as const,
};

function invalidateNotificationQueries(queryClient: ReturnType<typeof useQueryClient>) {
  void queryClient.invalidateQueries({ queryKey: NOTIFICATION_QUERY_KEYS.all });
  void queryClient.invalidateQueries({ queryKey: NOTIFICATION_QUERY_KEYS.unreadCount });
}

export function useMarkRead() {
  const queryClient = useQueryClient();
  const toast = useToastStore((s) => s.push);

  return useMutation({
    mutationFn: (notificationId: string) =>
      notificationApi.markRead(notificationId),

    // Optimistic update
    onMutate: async (notificationId) => {
      // Cancel outgoing queries để tránh ghi đè optimistic update
      await queryClient.cancelQueries({ queryKey: NOTIFICATION_QUERY_KEYS.all });

      // Lấy dữ liệu hiện tại từ cache để rollback nếu cần
      const previousData = queryClient.getQueriesData(NOTIFICATION_QUERY_KEYS.all);

      // Cập nhật tất cả notification queries: set isRead = true cho item tương ứng
      queryClient.setQueriesData(
        { queryKey: NOTIFICATION_QUERY_KEYS.all },
        (old: unknown) => {
          if (!old || typeof old !== "object") return old;

          // Handle PagedResult
          if ("data" in old && Array.isArray((old as { data: unknown[] }).data)) {
            return {
              ...old,
              data: (old as { data: { id: string; isRead: boolean }[] }).data.map(
                (item: { id: string; isRead: boolean }) =>
                  item.id === notificationId ? { ...item, isRead: true } : item
              ),
            };
          }

          return old;
        }
      );

      // Giảm unread count
      queryClient.setQueryData<{ count: number }>(
        NOTIFICATION_QUERY_KEYS.unreadCount,
        (old) => old ? { count: Math.max(0, old.count - 1) } : old
      );

      return { previousData };
    },

    // Rollback nếu lỗi
    onError: (_err, _variables, context) => {
      if (context?.previousData) {
        for (const [queryKey, data] of context.previousData) {
          queryClient.setQueryData(queryKey, data);
        }
      }
      toast({ title: "Không thể đánh dấu. Vui lòng thử lại.", tone: "error" });
    },

    onSuccess: () => {
      toast({ title: "Đã đánh dấu là đã đọc.", tone: "success" });
    },

    onSettled: () => {
      void queryClient.invalidateQueries({ queryKey: NOTIFICATION_QUERY_KEYS.unreadCount });
    },
  });
}

export function useMarkAllRead() {
  const queryClient = useQueryClient();
  const toast = useToastStore((s) => s.push);

  return useMutation({
    mutationFn: notificationApi.markAllRead,

    // Optimistic update
    onMutate: async () => {
      await queryClient.cancelQueries({ queryKey: NOTIFICATION_QUERY_KEYS.all });

      const previousData = queryClient.getQueriesData(NOTIFICATION_QUERY_KEYS.all);

      // Mark all items as read
      queryClient.setQueriesData(
        { queryKey: NOTIFICATION_QUERY_KEYS.all },
        (old: unknown) => {
          if (!old || typeof old !== "object") return old;

          if ("data" in old && Array.isArray((old as { data: unknown[] }).data)) {
            return {
              ...old,
              data: (old as { data: { isRead: boolean }[] }).data.map(
                (item: { isRead: boolean }) => ({ ...item, isRead: true })
              ),
            };
          }

          return old;
        }
      );

      // Reset unread count về 0
      queryClient.setQueryData<{ count: number }>(
        NOTIFICATION_QUERY_KEYS.unreadCount,
        { count: 0 }
      );

      return { previousData };
    },

    onError: (_err, _variables, context) => {
      if (context?.previousData) {
        for (const [queryKey, data] of context.previousData) {
          queryClient.setQueryData(queryKey, data);
        }
      }
      toast({ title: "Không thể đánh dấu tất cả. Vui lòng thử lại.", tone: "error" });
    },

    onSuccess: () => {
      toast({ title: "Đã đánh dấu tất cả là đã đọc.", tone: "success" });
    },

    onSettled: () => {
      void queryClient.invalidateQueries({ queryKey: NOTIFICATION_QUERY_KEYS.all });
      void queryClient.invalidateQueries({ queryKey: NOTIFICATION_QUERY_KEYS.unreadCount });
    },
  });
}
```
