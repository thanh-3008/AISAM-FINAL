# US-04 Frontend Detail - Xem thong tin tai khoan hien tai

## 1. User story

La nguoi dung da dang nhap, toi muon xem thong tin tai khoan hien tai de biet minh dang su dung dung account.

## 2. Muc tieu frontend

- Hien thi thong tin co ban cua tai khoan dang dang nhap.
- Dong bo frontend voi endpoint `me` hien co trong backend.
- Khong gia dinh backend tra day du profile/account metadata hon thuc te.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `docs/main/requirements.md` muc `6.1` yeu cau account management.

### Backend plan lien quan

- `docs/archive/plans/backend-code-plan.md` Phase 3 xac dinh `me` la endpoint Auth MVP.

### Backend implementation thuc te

- Endpoint: `GET /api/Auth/me`
- Authorization: bat buoc Bearer token
- Response shape: `GenericResponse<object>`
- Doi tuong `data` thuc te gom:
  - `id`
  - `email`
  - `fullName`
  - `role`

### Hanh vi backend can frontend phai follow

- Backend lay du lieu tu JWT claims, khong query database lai
- `isEmailVerified` khong nam trong response `me`
- `createdAt`, `lastLoginAt` khong nam trong response `me`
- Neu token khong hop le/het han, frontend se gap `401` tu auth middleware

## 4. Pham vi frontend

### Trong pham vi

- Trang `/account`
- Fetch du lieu current user bang endpoint `me`
- Hien thi thong tin co ban

### Ngoai pham vi

- Chinh sua profile user level: backend chua co endpoint update user account rieng trong nhom nay
- Doi mat khau: thuoc pham vi trang security, khong nam trong story nay

## 5. API contract can dung

### Request

`GET /api/Auth/me`

Header:

```http
Authorization: Bearer <accessToken>
```

### Success response

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "Current user retrieved successfully",
  "statusCode": 200,
  "data": {
    "id": "guid",
    "email": "user@example.com",
    "fullName": "User One",
    "role": "User"
  },
  "error": null
}
```

### Error response

- `401` khi token khong hop le hoac het han
- `500` khi loi he thong

## 6. UI/UX spec

### Route

- Route chinh: `/account`

### Thong tin can hien thi

- `Email`
- `Full name`
- `Role`
- `User ID` co the hien trong section ky thuat hoac account metadata

### State

- loading skeleton
- empty value placeholder cho `fullName` neu null
- error state neu fetch that bai

## 7. Validation frontend

- Khong co form input chinh trong story nay
- Chi can dam bao user phai authenticated truoc khi vao trang

## 8. Data flow frontend

1. User vao `/account`
2. Frontend kiem tra session
3. Goi `GET /api/Auth/me`
4. Neu thanh cong:
   - render thong tin account
5. Neu `401`:
   - auth flow xu ly refresh neu co
   - neu khong cuu duoc session, redirect `/login`

## 9. State can xu ly

### Loading state

- skeleton/placeholder cho account summary

### Error state

- generic error cho fetch fail

### Empty state

- `fullName` co the rong, frontend hien `Not provided`

## 10. Auth/session impact

- Story nay read-only
- Khong thay doi session
- Co the dung data trong auth store de render som, nhung can ton trong endpoint `me` la source revalidation

## 11. Dieu huong sau khi tai trang

- Khong redirect neu fetch thanh cong
- Redirect `/login` neu session khong hop le

## 12. Acceptance criteria

### AC-01

Frontend goi dung `GET /api/Auth/me` khi vao trang account.

### AC-02

Trang account hien thi duoc `email`, `fullName`, `role`, `id` tu backend.

### AC-03

Khi `fullName` null, UI van render on dinh voi placeholder hop ly.

### AC-04

Khi session khong hop le, frontend khong de user o trang loi vo nghia ma dua ve flow login.

## 13. Test cases frontend

### FE-01

Trang `/account` fetch `me` thanh cong va render du lieu.

### FE-02

`fullName = null` render placeholder.

### FE-03

`401` tu `me` dan den clear session va redirect `/login` neu refresh fail.

### FE-04

`500` tu `me` hien error state co the retry.

## 14. Ghi chu implementation

- Khong duoc viet UI dua tren gia dinh `me` tra `isEmailVerified` hoac `lastLoginAt`; backend hien tai khong tra.
- `role` trong `me` la claim value, co the la string.
- Neu can hien trang thai verify email, frontend nen lay tu auth session user duoc tra tu `login/register/refresh`, khong phai tu `me`.
