# US-20 Frontend Detail - Quan ly thu vien noi dung

## 1. User story

La nguoi dung, toi muon xem danh sach, chi tiet, cap nhat, xoa mem va khoi phuc content de quan ly ban nhap.

## 2. Muc tieu frontend

- Cung cap giao dien quan ly thu vien noi dung (content library) voi toan bo chuc nang lifecycle.
- Tao bang danh sach content co tim kiem, loc, sap xep va phan trang.
- Hien thi chi tiet content trong modal hoac trang detail.
- Ho tro cap nhat content truc tiep tu giao dien.
- Cho phep xoa mem (soft delete) content va khoi phuc (restore) khi can thiet.
- Lam viec voi backend API `ContentController` va `ContentService` dang active.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `docs/main/requirements.md` muc `6.7 Content Review and Approval` va `6.8 Publishing and Scheduling` xac dinh content phai co lifecycle va duoc quan ly.
- Content lifecycle co trang thai: `Draft`, `PendingApproval`, `Approved`, `Scheduled`, `Published`, `Rejected`.

### Backend plan lien quan

- `docs/archive/plans/backend-code-plan.md` Phase 5 va sau xac dinh `Content Management` la module da phat trien.
- `CODEBASE_UPDATE.md` xac nhan Content da active va da test voi `ContentController`, `ContentService`, `ContentRepository`.

### Backend implementation thuc te

#### Endpoints co san:

1. **List contents (paged)**
   - Endpoint: `GET /api/content`
   - Params: `page`, `pageSize`, `searchTerm`, `sortBy`, `sortDescending`, `brandId`, `adType`, `includeDeleted`, `status`
   - Response: `GenericResponse<PagedResult<ContentResponseDto>>`

2. **Get content detail**
   - Endpoint: `GET /api/content/{contentId}`
   - Response: `GenericResponse<ContentResponseDto>`

3. **Create content**
   - Endpoint: `POST /api/content`
   - Request: `CreateContentRequest`
   - Response: `GenericResponse<ContentResponseDto>`

4. **Update content**
   - Endpoint: `PUT /api/content/{contentId}`
   - Request: `UpdateContentRequest`
   - Response: `GenericResponse<ContentResponseDto>`

5. **Soft delete content**
   - Endpoint: `DELETE /api/content/{contentId}`
   - Response: `GenericResponse<bool>`
   - Hanh vi: dat `IsDeleted = true`, khong xoa du lieu that

6. **Restore content**
   - Endpoint: `POST /api/content/{contentId}/restore`
   - Response: `GenericResponse<bool>`
   - Hanh vi: dat `IsDeleted = false`, reset trang thai ve `Draft`

7. **Clone content**
   - Endpoint: `POST /api/content/{contentId}/clone`
   - Response: `GenericResponse<ContentResponseDto>`
   - Tao ban sao voi trang thai `Draft`

#### Model Content:

```
Content {
  id: Guid
  profileId: Guid
  brandId: Guid
  productId: Guid?
  adType: AdTypeEnum (TextOnly, ImageText, VideoText)
  title: string?
  textContent: string
  imageUrl: string? (JSON)
  videoUrl: string?
  styleDescription: string?
  contextDescription: string?
  representativeCharacter: string?
  status: ContentStatusEnum (Draft, PendingApproval, Approved, Rejected, Published)
  isDeleted: bool
  createdAt: DateTime
  updatedAt: DateTime
  brandName: string? (in DTO)
}
```

#### Validation backend:

- Content phai thuoc profile hien tai (`profileId` tu context)
- Brand phai ton tai va hop le
- Product neu co phai thuoc dung brand
- Chi content status la `Draft` moi co the cap nhat
- Soft delete: content phai ton tai va chua bi xoa
- Restore: content phai ton tai, da bi xoa (`isDeleted = true`)

## 4. Pham vi frontend

### Trong pham vi

- **Trang danh sach content**: `/dashboard/content` hoac `/content` tuong ung codebase
  - Bang (table) hien thi danh sach content voi columns: title, brand, type, status, created date, action
  - Loc va tim kiem:
    - Tim theo `searchTerm` (title)
    - Loc theo brand (`brandId`)
    - Loc theo type (AdType: TextOnly, ImageText, VideoText)
    - Loc theo trang thai status
    - Hien/an content da xoa (`includeDeleted` toggle)
  - Sap xep: tang/giam theo column (title, created date, updated date, etc.)
  - Phan trang: 10/20/50 item tren 1 trang

- **Row action**:
  - View detail (icon)
  - Edit (icon/button)
  - Clone (icon/button)
  - Delete (icon/button, confirm dialog)
  - Restore (icon/button, chi hien khi `isDeleted = true`)

- **Modal/page detail content**:
  - Hien thi day du thong tin content (read-only view)
  - Button: Edit, Clone, Delete, Restore, Close
  - Hien thi status va thoi gian tao/cap nhat

- **Edit content modal/page**:
  - Form chinh sua cac truong: title, brand, product, ad type, text content, image URL, video URL, style, context, character
  - Button: Save, Cancel
  - Validation client-side
  - Xu ly loading, error, success

- **Delete confirm dialog**:
  - Confirm: xoa mem (isDeleted = true)
  - Button: Delete, Cancel

- **Restore confirm dialog** (khi content da xoa):
  - Confirm: khoi phuc content
  - Button: Restore, Cancel

- **Trang tao/cap nhat content**: da thuoc `US-19` va `US-21`, chi lien ket toi day

### Ngoai pham vi

- Approval workflow: thuoc `US-58` sau MVP
- Publishing: thuoc `US-34` va `US-40`
- Analytics detail: thuoc `US-43` va `US-67`
- AI generation manage: thuoc `US-22`, `US-23`, `US-24`, `US-25`
- Conversation AI: thuoc `US-26`

## 8. Data flow frontend

### Flow view list

1. User vao `/dashboard/content`
2. Frontend trig `GET /api/content` voi params default: `page=1, pageSize=10, includeDeleted=false`
3. Backend tra list + total count
4. Frontend render bang voi data va pagination
5. User thay doi filter/search:
   - Frontend cap nhat query params
   - Trig lai `GET /api/content` voi params moi
   - Render bang update

### Flow view detail

1. User click icon view (👁) tren row
2. Frontend fetch `GET /api/content/{contentId}`
3. Backend tra chi tiet
4. Frontend hien modal detail voi data

### Flow edit

1. User click icon edit (✏️) tren row hoac button Edit trong detail
2. Frontend fetch `GET /api/content/{contentId}` (neu chua co)
3. Frontend mo edit modal voi form pre-filled
4. User edit fields va click Save
5. Frontend validate form
6. Frontend trig `PUT /api/content/{contentId}` voi updated data
7. Backend update
8. Frontend:
   - Dong modal
   - Refresh list (trig `GET /api/content` voi current params)
   - Hien success toast

### Flow delete

1. User click delete icon (✗)
2. Frontend hien confirm dialog: "Are you sure you want to delete this content?"
3. User confirm
4. Frontend trig `DELETE /api/content/{contentId}`
5. Backend soft delete (isDeleted = true)
6. Frontend:
   - Dong dialog
   - Refresh list
   - Hien success toast

### Flow restore

1. User enable toggle "View deleted" hoac content hien ra neu giu toggle on
2. User click restore icon (↩)
3. Frontend hien confirm dialog: "Restore this content?"
4. User confirm
5. Frontend trig `POST /api/content/{contentId}/restore`
6. Backend restore (isDeleted = false, status = Draft)
7. Frontend:
   - Dong dialog
   - Refresh list
   - Hien success toast

### Flow clone

1. User click clone icon hoac button trong detail
2. Frontend trig `POST /api/content/{contentId}/clone`
3. Backend clone va tra new content voi status Draft
4. Frontend:
   - Refresh list
   - Hien success toast: "Content cloned successfully"
   - Tuong tu co the auto-scroll toi cloned content

## 9. State can xu ly

### Loading state

- Disable buttons/controls trong dialog khi pending
- Show spinner/skeleton trong bang khi load list
- Doi label button thanh "Saving..." hoac "Deleting..."

### Success state

- Toast message: "Content updated successfully", "Content deleted successfully", etc.
- Refresh list tu backend
- Dong dialog (neu modal)
- Clear form state

### Error state

- Hien error message:
  - Validation errors field-level (neu co `validationErrors` trong response)
  - General error: doc tu `error.errorMessage` hoac `message`
  - Generic: "An error occurred, please try again"
- Giu form state de user sua lai
- Enable buttons again

### Empty state

- Neu list rong: hien "No content found"
- Co thoi gian, nuoi user tao moi content

### Deleted state

- Neu `isDeleted = true` trong view detail, hien badge "Deleted"
- Chi hien restore button, ko hien edit/delete button
- Neu toggle "View deleted" off, an row deleted khoi table

## 10. Auth/session impact

- Cac endpoint yeu cau `Authorization: Bearer <accessToken>`
- Backend enforce ownership: chi la chi tiet content cua profile hien tai moi co quyen
- Frontend phai set active profile context truoc call content API
- Neu token het han, auto-refresh hoac redirect login

## 11. Dieu huong sau action

### Sau create/update/delete/restore:

- Refresh list (trong same view)
- Hien success toast
- Dong modal (neu co)
- Hang loading khi refresh (tuong tac voi user chat, khong bi freeze UI)

### Sau clone:

- Success toast
- Refresh list
- Tuong tac: co the auto-scroll toi cloned row hoac hien highlighting

## 14. Ghi chu implementation

- Backend da co toan bo API va business logic, frontend chi can consume.
- `isDeleted` la soft delete flag, khong xoa that du lieu, chi an khoi list (khong `includeDeleted`).
- Restore tu dong reset status ve `Draft` (theo backend logic).
- Frontend khong phai implement complex approval flow o phia US-20, chi hien trang thai status.
- Neu so luong content lon, consider add virtual scroll hoac infinite scroll thay pagination.
- File upload (image, video URL) dang outside scope US-20, chi handle URL string.
- Brand va Product dropdown phai load tu API (thuoc scope khac).
