# US-03 Frontend Detail - Lam moi phien dang nhap

## 1. User story

La nguoi dung da dang nhap, toi muon frontend tu dong lam moi phien dang nhap de toi khong bi vang ra khoi he thong qua som.

## 2. Muc tieu frontend

- Tich hop token refresh theo contract backend hien tai.
- Gia han session mot cach trong suot voi nguoi dung.
- Xu ly dung khi refresh that bai: xoa session va dua user ve `/login`.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `docs/main/requirements.md` muc `6.1` yeu cau he thong ho tro `JWT-based authentication` va `refresh token`.

### Backend plan lien quan

- `docs/archive/plans/backend-code-plan.md` Phase 3 xac dinh `refresh` la endpoint bat buoc cua Auth MVP.

### Backend implementation thuc te

- Endpoint: `POST /api/Auth/refresh`
- Request DTO:
  - `refreshToken`
- Response: `GenericResponse<TokenResponse>`
- HTTP success: `200 OK`

### Hanh vi backend can frontend phai follow

- Backend se tim session theo refresh token
- Neu refresh token invalid, revoked, inactive hoac het han:
  - tra `401 Unauthorized`
  - message: `Invalid or expired refresh token`
- Neu thanh cong:
  - revoke session cu
  - tao session moi
  - tra access token + refresh token moi

## 4. Pham vi frontend

### Trong pham vi

- API refresh token
- Auth store update session
- Auto refresh trong API client
- Session expired handling

### Ngoai pham vi

- UI man hinh rieng cho refresh token: khong can
- Dang nhap lai thu cong: thuoc `US-02`

## 5. API contract can dung

### Request

`POST /api/Auth/refresh`

```json
{
  "refreshToken": "string"
}
```

### Success response

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "Token refreshed successfully",
  "statusCode": 200,
  "data": {
    "accessToken": "string",
    "refreshToken": "string",
    "expiresAt": "2026-06-02T00:30:00Z",
    "tokenType": "Bearer",
    "user": {
      "id": "guid",
      "email": "user@example.com",
      "fullName": "User One",
      "role": 0,
      "isEmailVerified": false,
      "createdAt": "2026-06-01T00:00:00Z",
      "lastLoginAt": "2026-06-02T00:00:00Z"
    }
  },
  "error": null
}
```

### Error response

- `401` neu refresh token khong hop le/het han
- `500` neu loi he thong

## 6. UI/UX spec

### UI truc tiep

- Khong can man hinh rieng cho refresh
- Can co UX cho session het han:
  - toast/banner `Session expired. Please login again.`

### Vi tri xay ra

- Khi user mo app voi token cu
- Khi user goi API protected va access token het han

## 7. Validation frontend

- Chi goi refresh khi co `refreshToken`
- Neu khong co refresh token thi khong duoc goi API refresh, phai xoa session ngay

## 8. Data flow frontend

1. App boot hoac truoc khi goi protected API
2. Frontend kiem tra `expiresAt`
3. Neu token gan het han hoac da het han:
   - goi `POST /api/Auth/refresh`
4. Neu thanh cong:
   - cap nhat `accessToken`
   - cap nhat `refreshToken`
   - cap nhat `expiresAt`
   - cap nhat `user`
5. Neu that bai:
   - clear auth store
   - clear active profile neu dang co
   - redirect `/login`
   - hien thong diep session het han

## 9. State can xu ly

### Silent loading state

- Refresh dien ra ngam, khong can blocker UI full page trong mọi tinh huong

### Failure state

- Session het han
- Redirect ve public area

## 10. Auth/session impact

- Refresh thay the session cu bang session moi
- Frontend khong duoc giu refresh token cu sau khi refresh thanh cong
- Can tranh goi refresh nhieu lan song song

## 11. Dieu huong sau refresh

- Neu refresh thanh cong: giu nguyen route hien tai
- Neu refresh that bai: redirect `/login`

## 12. Acceptance criteria

### AC-01

Khi access token het han nhung refresh token con hop le, frontend goi dung API refresh va cap nhat session.

### AC-02

Khi refresh thanh cong, user tiep tuc su dung app ma khong bi vang ra.

### AC-03

Khi refresh tra `401`, frontend xoa session va redirect `/login`.

### AC-04

Frontend khong duoc de xay ra vong lap refresh vo han.

## 13. Test cases frontend

### FE-01

Co `refreshToken` hop le va access token het han se goi API refresh.

### FE-02

Refresh thanh cong se cap nhat auth store bang token moi.

### FE-03

Refresh tra `401` se clear session va redirect `/login`.

### FE-04

Nhieu request protected cung gap token het han chi kich hoat mot luong refresh an toan.

## 14. Ghi chu implementation

- Backend rotate refresh token moi lan refresh, frontend phai overwrite refresh token cu.
- Khong coi `me` la refresh endpoint; endpoint dung la `POST /api/Auth/refresh`.
- Story nay la logic nen cua API client/auth store, khong phai page UI rieng.
