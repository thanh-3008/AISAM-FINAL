# US-10 Frontend Detail - Dat lai mat khau bang token

## 1. User story

La nguoi dung nhan duoc link reset password, toi muon dat lai mat khau moi de dang nhap lai vao AISAM.

## 2. Muc tieu frontend

- Cung cap trang reset password nhan `email` va `token` tu link hoac form.
- Goi dung contract backend hien tai.
- Hien success state de user quay ve login.

## 3. Can cu backend va scope hien tai

### Requirement lien quan

- `docs/main/requirements.md` muc `6.1` co `dat lai mat khau`.

### Backend implementation thuc te

- Endpoint:
  - `POST /api/Auth/reset-password`
  - `POST /api/Auth/change-password-with-token`
- Ca hai deu nhan `ResetPasswordRequest`
- Frontend story MVP nen bam endpoint `reset-password` cho flow quen mat khau

### Request DTO thuc te

- `email`
- `token`
- `newPassword`
- `confirmPassword`

### Hanh vi backend can frontend phai follow

- Backend thuc te lookup bang `token`
- Neu token invalid/expired:
  - `400 Bad Request`
  - message `Invalid or expired reset token`
- Neu thanh cong:
  - `200 OK`
  - message `Password reset successfully. Please login with your new password.`
- Backend revoke tat ca sessions cua user sau reset

## 4. Pham vi frontend

### Trong pham vi

- Trang `/reset-password`
- Doc `token` va co the doc `email` tu query string
- Form nhap mat khau moi
- Submit reset password

### Ngoai pham vi

- Forgot password request: thuoc `US-09`
- Change password khi da login: thuoc security scope khac

## 5. API contract can dung

### Request

`POST /api/Auth/reset-password`

```json
{
  "email": "user@example.com",
  "token": "reset-token",
  "newPassword": "NewPassword@123",
  "confirmPassword": "NewPassword@123"
}
```

### Success response

HTTP: `200 OK`

```json
{
  "success": true,
  "message": "Password reset successfully. Please login with your new password.",
  "statusCode": 200,
  "data": null,
  "error": null
}
```

### Error response

- `400` khi token invalid/expired
- `500` khi loi he thong

## 6. UI/UX spec

### Route

- `/reset-password`

### Form fields

1. `email`
   - required
2. `token`
   - co the an di neu da co trong query string
3. `newPassword`
   - required
   - min 8
4. `confirmPassword`
   - required
   - phai giong `newPassword`

### CTA

- `Reset password`

### Success UX

- Hien message thanh cong
- CTA `Back to login`

## 7. Validation frontend

- `email` required
- `token` required
- `newPassword` required, min 8
- `confirmPassword` required, phai khop `newPassword`

## 8. Data flow frontend

1. User mo link reset password
2. Frontend doc `token` va co the doc `email` tu URL
3. Render form reset
4. User nhap mat khau moi
5. Goi `POST /api/Auth/reset-password`
6. Neu thanh cong:
   - hien success state
   - cho user ve `/login`
7. Neu that bai:
   - hien error state token invalid/expired hoac loi he thong

## 9. State can xu ly

### Loading state

- Disable CTA

### Success state

- Password reset thanh cong

### Error state

- Missing token
- Invalid/expired token
- Validation loi

## 10. Auth/session impact

- Story nay khong login user tu dong
- Neu user dang co session o browser hien tai, backend co the revoke session cu; frontend nen uu tien redirect ve login sau khi success

## 11. Dieu huong sau reset

- CTA / redirect sau success: `/login`

## 12. Acceptance criteria

### AC-01

Frontend gui dung request reset password theo contract backend.

### AC-02

Khi reset thanh cong, frontend hien thong diep de user dang nhap lai.

### AC-03

Khi token invalid/expired, frontend hien error ro rang va khong redirect nham vao protected area.

### AC-04

Frontend validate `confirmPassword` khop `newPassword`.

## 13. Test cases frontend

### FE-01

Missing token hien error state va khong submit.

### FE-02

`confirmPassword` khong khop thi chan submit.

### FE-03

Submit thanh cong hien success state va CTA ve login.

### FE-04

API tra `400 Invalid or expired reset token` hien message phu hop.

## 14. Ghi chu implementation

- Backend hien co them endpoint `change-password-with-token` dung chung service; story forgot-password reset nen bam `reset-password`.
- Dung backend policy min 8 ky tu, khong them complexity khac neu chua co o BE.
- `email` van nam trong DTO backend, frontend nen gui day du du backend dang lookup bang token.
